# v0.9 Retire `csp::lower` and `lang::emit`; Functional Checks on Tile Contents (retire-l0-derivations PR 2)

**Date:** 2026-10-11
**Version:** v0.9
**Status:** Complete (PR 2 of 3; a PR 4 is proposed for review)
**Tests:** 270/270

## 1. Summary

#358 (PR 1, the L-B oracle) was merged. PR 2 retires the two paths that turned an L0 back into a
program. It also introduces the functional-check layer the user specified at the start of this
PR.

## 2. Decisions

- **Functional checks are made on tile contents, interpreted, within a proximity bound**
  (decided by the user, 2026-10-11). The user's direction, in substance:
  - a machine's functional behaviour is the sequence of tile moves through the resources, and
    the bits of the result;
  - floating point is not associative, and the data path executes reductions and quantization
    conversions under many constraints;
  - so value checks belong on tile contents, through an interpretation layer that reads the bits
    in the intended format and asserts proximity within an epsilon.

  Built as `include/sw/kpu/program/tile_check.hpp`:
  - `ElementFormat` is the interpretation. Float32 is decoded; any other format is refused by
    name, because operands store float32 today, and checking a bf16 tile as float32 would be
    wrong silently.
  - `Proximity` is ADR 0001 D5's per-element comparator. `proximity_for(format)` gives
    float32's default (atol 1e-6, rtol 1e-4).
  - `check_tiles` walks the tile grid, clamped trailing tiles included. It reports each tile out
    of bound with its first element, and the worst absolute and relative error.
  - A different grid is thrown as a structural failure, never bounded as a value.
- **Scope.** This PR applies the layer to the checks it writes or moves (`test_csp_driver`,
  `test_csp_program`). Moving the rest is proposed as PR 4 and recorded in the plan for review
  (§3.8, Q4):
  - kpu-run's level comparison, `run_csp`, and the CSP and platform suites;
  - amending ADR 0001 D5 and the `CLAUDE.md` fidelity table.
  - I recommend that the trace's replay validation stay bit-exact. It checks that a trace
    records its run, which is not a functional check of the machine.
- **The tile-move sequence is checked exactly**, as before: DRAM loads equal the program's loads,
  stores, every L3 credit returned, and the DMA's credit order equal to program order.
- **`test_csp_driver` runs written programs.**
  - The S1 256³/32³ program is kpu-csp-gen's column-panel matmul: 576 DRAM loads, which is B's
    64 tiles plus A's 8-tile row panel per (j, i), and 64 stores. The Belady-lowered program had
    128 loads.
  - The "reloads, one for one" test was lowering at L3 4, 8 and 16. It now runs three schedules
    of one matmul: the hand-written A-whole program, and kpu-csp-gen's column and row panels.
  - CspDriver's refusal now says "written for an L3 of N tiles". The unbounded case sets the
    compiled program's L3 capacity to 0.
- **`test_csp_program` keeps the tests of the program form**, now on compiled programs: process
  ownership, the read-after-release refusal, L-B values for matmul (col and row) and LU, and LU's
  16 loads and 16 stores.

## 3. Removed, with why

All of these test the retired paths, not the simulator:
- `test_csp_program`:
  - "matmul on S1's 128 slots loads every tile exactly once";
  - "a smaller L3 reloads exactly what Belady must", with its optimal-load DP;
  - "an op whose tiles cannot all fit the L3 is refused";
  - "an explicit program whose call reads an unfed tile is refused";
  - the lowered matmul and LU value sections, including tight LU at 3 slots.
- `test_csp_language`: "derived L0 is emitted as a program that compiles and computes the
  reference".
- `test_csp_linear`: "the lowered L0 runs at L-B", and the emitter's "placed by a tile context"
  refusal.

The value checks in `test_csp_driver` changed from whole-operand bit equality to per-tile
proximity against L-B, by the decision above. The two bit-equality checks in its S1 test (against
the L0 reference and against L-B) became one tile check against L-B.

## 4. Wrong decisions

- **I saturated the shared build machine**, at a load average of about 245 on 12 cores. The user
  stopped it.
  - Cause: I started a second full `ninja -k 0` while the first was still running. That build
    had hit a compile error, but `-k 0` kept it going, and its chained ctest still ran. With
    `-flto=auto`, every link also spawns about nproc `lto1` jobs: roughly 28 links and 212 `lto1`
    processes at once.
  - Fix: builds now run as `nice -n 19 cmake --build build -j 2` and tests as `ctest -j 4`, only
    after checking that no build is running. Saved to memory.
- **A text cut removed three helpers.** Cutting `test_csp_language`'s emission helper took
  `count`, `same_actions` and `compile_error` with it, because the cut ran to the next
  `TEST_CASE` rather than the end of the helper. The build caught it, and the helpers were
  restored from main.
