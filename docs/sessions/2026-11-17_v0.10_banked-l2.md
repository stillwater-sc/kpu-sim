# Session: L-CA's L2 is banked (#401, slice 1)

**Date:** 2026-11-17
**Version:** v0.10 (in progress)
**Issue:** #401 (slice 1 of several; plan `docs/plans/banked-l2-at-lca.md`)

## 1. Summary

L-CA's L2 was one pool of tile-sized slots, with every transfer at its rate. Now a compute tile's
L2 is banks of rows (row i in bank i mod N). Each bank has 2 read ports and 1 write port per clock,
and reads have a 4-clock latency. Every L2 transfer books its rows on their banks' ports, and a row
that finds them taken waits a clock.

## 2. Technical Decisions (the user's, 2026-11-17)

- **Slice: banked L2 first.** The other slices build on it.
- **Geometry:** the `systolic` scratchpad, else `l2.banks_per_tile` with named defaults. Neither
  declared: pooled.
- **Ports:** esg#24's idealized 2R + 1W per bank, and a stall on a conflict. Macro-typed ports later.
- **Rollout:** re-baseline every test whose cycles move, with old and new cycles in the PR.
- **Mine:** a reservation calendar, not per-clock stepping. The processes compute a transfer's
  duration when it starts, so the transfer books its rows then, in tick order. That keeps the
  movers' and streamers' structure. With no read latency and no conflicts it gives exactly the
  pooled timing, which was checked (below).

## 3. Issues Encountered

- **os got faster with banks** (4049 → 4006 cycles on S1 with a Combiner), though banked reads are
  only slower. With the read latency set to 0, os and ws give exactly the pooled cycles (4049,
  5042). So the calendar is sound, and the 43 cycles come from the latency reordering work: the
  longer feeds change when the movers take their credits. That's a scheduling effect, like the
  window effect in #424.
- `test_resource_map` declared 3 L2 banks, which is now refused. It uses 4.
- `test_csp_driver`'s window rule ("from 16 up, within 2%") is 3.8% off with S1's banks. It's
  already pinned to the legacy rates for #462, and is now pinned to the pooled L2 too.

- CI's MSVC build failed two claims that gcc and clang passed: staged faster than unstaged (now
  "no slower": the margin is a few cycles, and MSVC's DMA timing differs by a cycle or two), and no
  Streamer stall under ws and is (the Combiner's read-modify-write competes for the read ports, the
  first to book wins). The claims now say what holds.
- The review found the drain booked its rows before the fabric's epilogue and on tile 0's banks,
  the executor's reset kept the calendar, 4-bit rows were rounded per element, and a deployment
  could declare a bank count the scratchpad overrode. Each is fixed with a regression.

## 4. Wrong Decisions

- None.
