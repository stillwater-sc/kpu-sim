# v0.9 Zero-Warning Builds (-Werror / /WX) Decision Log

**Date:** 2026-06-27

**Status:** Complete
**Tests:** CI green on all platforms (gcc, clang, MSVC build + ctest), benchmark + Snyk passing

## 1. Summary

Drove PR #31 (`ci: lock in zero-warning builds with -Werror / /WX`, #23 Phase 3) to a
fully green CI and merged it to `main`. The PR enables warnings-as-errors across the three
CI compilers. gcc was already clean, but clang and especially MSVC `/W4` surfaced large
classes of conversion warnings that the GNU `-Wall -Wextra` builds never report. Because a
warnings-as-errors build stops at the first error, these warnings only appeared one file at
a time on CI (each round ~6–17 min on the Windows runner). Rather than iterate file-by-file,
each warning class was enumerated wholesale with a targeted local clang scan that acts as a
faithful proxy for the corresponding MSVC class, fixed in parallel batches, and verified
locally under `release-werror` with both gcc and clang before each push. ~800 narrowing
sites were made explicit with behavior-preserving `static_cast`s, plus one build-config flag
(`/utf-8`) and two small source fixes.

## 3. Technical Decisions

**Decision 1: Enumerate each MSVC warning class via a local clang scan instead of iterating on CI**
- **Choice:** For each MSVC class, build locally with `cmake --preset release` plus the
  matching clang flag(s) and *without* `-Werror` (`ninja -k 0`) to collect every site at once,
  then fix in one batch.
- **Alternatives Considered:** Push one fix, wait for the next MSVC failure, repeat.
- **Rationale:** Each CI round is ~6–17 min and the build stops at the first error, so
  file-by-file iteration would have taken many hours. clang's `-Wshorten-64-to-32` +
  `-Wimplicit-int-conversion` is a faithful superset of MSVC `C4267`/`C4244` integer
  narrowings; `-Wimplicit-int-float-conversion` + `-Wfloat-conversion` matches `C4244`
  float narrowings (both fire only on genuinely lossy conversions). Validated each proxy by
  confirming the actual MSVC failure sites appeared in the corresponding clang scan output.
- **Files:** local scan build dirs only (not committed).

**Decision 2: Fix narrowings with site-level `static_cast`, not signature/type changes**
- **Choice:** Wrap the minimal offending sub-expression in `static_cast<DST>(...)` at each site.
- **Alternatives Considered:** Widen parameter/member types; disable the warnings (`/wd4244`
  etc.); restructure the arithmetic.
- **Rationale:** Matches the PR's established per-site style, keeps diffs local and safe, and
  is provably behavior-preserving — the cast makes explicit the exact conversion the compiler
  was already performing implicitly. Disabling the warnings would defeat the PR's purpose.
- **Files:** 38 files (integer pass) + 152 files (float pass); see CHANGELOG entry.

**Decision 3: `/utf-8` for `C4566` instead of stripping Unicode**
- **Choice:** Add `/utf-8` to the MSVC `CMAKE_CXX_FLAGS` (scoped to the `elseif(MSVC)` branch).
- **Alternatives Considered:** Replace the arrows/box-drawing glyphs with ASCII; use `u8""`
  literals.
- **Rationale:** ~175 source files contain Unicode glyphs in trace/demo output; stripping
  them is massive churn and loses intended output. `/utf-8` sets both source and execution
  charset to UTF-8 (the encoding the sources are authored in), fixing all of them via one
  line. gcc/clang builds are unaffected.
- **Files:** `CMakeLists.txt`.

**Decision 4: Parallel sub-agents for the mechanical batches**
- **Choice:** Fan out the 169 integer sites across 7 agents and the 626 float sites across
  12 agents, each owning a disjoint set of files (no edit conflicts), with explicit rules.
- **Alternatives Considered:** Do all edits sequentially in the main loop.
- **Rationale:** The edits are mechanical but voluminous; disjoint file ownership lets them
  run concurrently with no merge risk, and a final clang scan verifies the whole result.
- **Files:** as above.

## 4. Issues Encountered

- **Edited on `main` initially.** The first two fixes were made before switching to the PR
  branch. *Fix:* stashed, checked out `ci/lock-in-warnings-as-errors`, popped — changes
  applied cleanly. No bad commit landed on `main`.
- **Float worklist de-duplication dropped second operands.** Ratio lines like
  `100.0 * a / b` contain two identical `uint64→double` conversions; `sort -u` on
  (file:line:message) collapsed them to one entry, so agents often cast only the numerator.
  The rescan still reported 400 raw warnings (47 unique lines). *Fix:* re-extracted the
  current remaining set from the verify log and cast the uncast denominator/operand on each.
- **Per-line cast script dropped enclosing parens on 4 lines.** A `find`/`replace` that
  matched `/ denom)` where `)` closed the *surrounding* expression produced unbalanced
  parens (compile errors in 3 TUs). *Fix:* re-added the closing paren on the 4 affected
  lines; rescan confirmed 0 errors and 0 narrowings.
- **clang scan is an imperfect MSVC proxy.** Two pybind `ssize_t → int` axis fixups in
  `kpu_native.cpp` were flagged by MSVC `C4244` but not by clang `-Wshorten-64-to-32`
  (clang value-range analysis), so the integer batch missed them. *Fix:* cast both after
  MSVC surfaced them; confirmed via grep that they were the only such sites in the file.

## 5. Wrong Decisions (CRITICAL)

- **Briefly considered `-Wimplicit-int-float-conversion` (non-const) as the full float
  proxy.** That scan reported 4411 sites because it also flags benign small-`int → float`
  conversions that MSVC `/W4` tolerates. Using it verbatim would have produced a large
  amount of unnecessary churn on non-MSVC issues. *Correction:* restricted the float worklist
  to `→ double` and lossy `→ float` targets (the genuinely lossy set), which matches what
  MSVC actually flags. *Lesson:* validate a proxy against the real failing sites before
  trusting its total count; an over-broad warning flag is not a faithful proxy.

No failing tests were skipped or masked; no completion was declared with broken
functionality. Every push was preceded by a clean local `release-werror` build on both gcc
and clang plus a zero-narrowing scan.

## 7. Next Steps

- The `-Werror` / `/WX` gate is now locked in on `main` for all three compilers. Future PRs
  must keep builds warning-free.
- If new MSVC `/W4` classes appear later in the build order (e.g. shadowing `C4456-9`,
  `C4127`), enumerate them with the corresponding clang flag and fix per-site as done here.
- The local scan-flag approach (clang flags as MSVC proxies) is a reusable recipe for any
  future cross-compiler warning cleanup; consider documenting it in CONTRIBUTING.
