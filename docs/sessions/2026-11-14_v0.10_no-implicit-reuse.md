# v0.10 L-CA Finds No Reuse of Its Own (#424)

**Date:** 2026-11-14
**Version:** v0.10
**Status:** Complete.
**Tests:** gcc, the full suite: 323/323. clang, the full suite: 322/322.

## 1. Summary

The user's rule (2026-11-14): reuse must be deliberate, stated in the CSP program's data
movement. All pipelined tiling depends on it. Without it, bandwidth and latency cannot keep a
high-performance systolic array fed, and the array has bubbles.

L-CA's BlockMover deduplicated Moves: a Move whose tile was still in L2 completed on that copy,
with no transfer. That is reuse no program stated. Now a CSP program's Move always transfers. If
an earlier copy of the tile is still in L2, the new copy lands beside it and holds its own L2
credit (`TagCAM::insert_copy`). Each copy's credit returns when a consumer reads it. The dedup
stays for the legacy schedule path (`ordered` is false there).

## 2. What it changed

| Program | Before | After |
|---|---|---|
| matmul 128³ in 32³ tiles on kpu_s1, whole program handed over | 9985 cycles | 15760 |
| the same, window 64 | 13536 | 15974 |
| the same, windows 1-16 | unchanged | unchanged |
| L2-staging test, unstaged | 4400, 80 transfers of 128 Moves | 5328, 128 transfers |
| L2-staging test, staged | 4400 | 4400 |

So the implicit reuse made L-CA's whole-program matmul 37% faster than its program. Staging now
pays at L-CA, as it does at L-T1.

## 3. Technical Decisions

- **Decision 1: a copy, not a wait.**
  - **Choice:** the second Move of a tile still in L2 lands a second copy with its own credit.
  - **Alternative:** the second Move waits until the first copy has left L2.
  - **Rationale:** the hardware has two L2 slots for the two copies, and can overlap the second
    transfer with the first copy's feed. Waiting would add a bubble the hardware does not have,
    which is as wrong as hiding one. The TagCAM is keyed by tile, so the entry counts its copies,
    and a credit returns each time the references left need one copy fewer.
- **Decision 2: the dedup stays for the legacy schedules.** They emit one Move per use and rely
  on it (#61). Only `ordered` (CSP) Moves are exempt.
- **Decision 3: the window test asserted something the reuse made true.** It said a window can
  never be faster than handing over the whole program. Without the reuse, a window of 16 is 0.7%
  faster: handed everything, the mover runs ahead and holds L2 credits that nearer Moves need,
  a real effect of greedy credit use. The test now asserts that window 1 is the slowest and that
  every window of 16 or more is within 2% of the whole program.
