## 3. Technical Decisions

- **Decision 1: reservation bound = peak_live_tiles + retained (Q1 default).** Alternative: an
  exact per-operator minimum found by searching capacities. Chosen because the bound has a proof,
  and a sweep confirms it is sufficient (it is also tight: the bound minus one fails).
- **Decision 2: manifests are derived on the device side (Q2 default).** No format change.
- **Decision 3: names in-process, indices on the wire** (plan §8.1). This keeps the trace
  readable and increment 2's tests intact.
- **Decision 4: R3 counts slots only for a prefetch** (plan §8.3).
- **Decision 5: the orchestrator checks its held set against `ST_HELD` before each operator.**
  This was added after the first mutation showed the orchestrator read no status register, so the
  non-interference test was blind to status leaks.
- **Decision 6: `RELEASE` moves before `LAUNCH`, and completions are posted out of order.** One
  increment 2 test now matches completions by id instead of by position.

## 4. Wrong decisions / lessons

- **The first isolation test was vacuous.** It accepted any `BusFault`, and an unmapped
  address also faults, so it passed with the tensor mapping deleted. It now requires the fault to
  name the tensor. Lesson: an absence-test must distinguish the absence it guards from a nearby one.
- **The first non-interference design could not see status leaks**, because the orchestrator
  read no status register. A test of "what the orchestrator observes" bounds only what the
  orchestrator actually observes.
- The plan's step 8 (the freestanding guard) was planned without checking the header graph. It
  is deferred and the reason is recorded (plan §8.5), not quietly dropped.
