# v0.9 kpu-run: Stepping L-CA, One Cycle per Step (#285)

**Date:** 2026-11-15
**Version:** v0.9
**Status:** in review (draft PR). With it, #285's last missing criterion that kpu-sim can meet
on its own is met. "All four levels" needs L-T2, which is #283's.
**Tests:** see §6.

## 1. Summary

`--step` walked L-B (one action applied per step) and L-T1 (a replay of its records). L-CA was
refused ("L-CA's step is a cycle, #283"). #285 asks for every level to step at its own
granularity, and L-CA's is the cycle. L-CA now steps a replay of its protocol events, one cycle
per step.

## 2. Scope

| Item | Status | Tests |

| `kpu-run --step` at L-CA, the finest level that ran | done | `kpu_run_csp_step_lca` |

## 3. Technical Decisions

- **Decision 1: a replay, not a paused executor.** The reason is L-T1's (driver plan increment
  3): the executor's schedule depends on the whole program, and pausing it mid-flight would make
  a different executor. Values cannot be inspected mid-replay, as at L-T1.
- **Decision 2: the events are kept only when asked for.** A run of any size would otherwise
  copy its whole event log into the outcome. Only `step_begin` asks, and the test checks that a
  plain run keeps none.
- **Decision 3: a step is a cycle at which something happened.** A cycle with no events leaves
  the machine's state unchanged.
- **Decision 4: a completion is placed at the cycle it ends.** The executor stamps COMPLETE
  events Chrome-trace style, at the transfer's start with a duration. The driver adds the
  duration, so a completion appears where it happens and in-flight counts balance.
- **Decision 5: a stall is listed when it begins.** A waiting process logs its stall every
  cycle, and the first replay printed almost every cycle as a step. A stall logged by the same
  process, on the same tile, on the cycle before is counted (`stalls_continuing`), not listed.
- **Decision 6: `--step` walks the finest level that ran**, which is L-CA when it ran, as it
  was already L-T1 over L-B.
- **Decision 7: a buffer slot is printed only for the event families that set one** (DMA, BM,
  CREDIT). The streamers' and the fabric's events leave it at its default of 0, and printing
  that would show a slot that does not exist.

## 4. Issues Encountered

- **The first replay was unreadable:**
  - the completions sat at their start cycle, and nothing was ever in flight;
  - every cycle carried the same stalls again.

  Both are fixed (Decisions 4 and 5). The 48x48 matmul on S1 runs 1948 cycles and steps 294.

## 5. Wrong Decisions

- None.

## 6. Verification

```bash
build/tools/kpu-run/kpu-run --program tests/program/corpus/matmul_48x48x48_t16.csp \
    --deploy tests/program/deploy/kpu_s1.json --level cycle-accurate --step --step-limit 12
build/tests/program/test_csp_step
(cd build && ctest -R kpu_run_csp_step)
```

`test_csp_step` checks the replay on matmul and the fused linear:
- cycles strictly increase;
- every event of the run is replayed exactly once, listed or counted;
- the DRAM loads and stores replayed match the run's;
- every tile named is one of the program's;
- every transfer begun has ended at the last step;
- the run behind the replay computes the same values and makespan as a plain run.

It also checks that L-CA on T4, and L-T2, are refused with their reasons.
