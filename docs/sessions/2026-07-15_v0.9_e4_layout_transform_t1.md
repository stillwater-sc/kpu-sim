## 3. Technical Decisions

### Decision 1: Use a closed generalized descriptor

- **Choice:** One versioned descriptor shares source/destination keys, rank/shape,
  element size, admission, timing, completion, and trace fields. Its kind is closed to
  identity, rank-2 transpose, compact reshape, head split/merge, and patchify.
- **Alternatives Considered:** A boolean transpose flag; separate unrelated operand
  structs; an arbitrary axis/stride/index permutation primitive.
- **Rationale:** The current boolean is erased before payload handling, while an
  arbitrary index engine exceeds current rank, serializer, TagCAM, timing, and oracle
  support. Closed named maps share infrastructure without weakening validation.
- **Files Modified:** `docs/plans/e4_layout_transform_pattern.md`.

### Decision 2: Materialize transforms privately and publish atomically

- **Choice:** BlockMover owns a complete private reorder allocation, transforms only
  after source arrival, and atomically publishes the L2 payload/TagCAM key at modeled
  completion before returning the source reference.
- **Alternatives Considered:** Host/DRAM pre-materialization; annotation-only movement;
  visible fragment streaming; zero-copy reshape aliasing.
- **Rationale:** The chosen model exposes real latency, reorder pressure, destination
  backpressure, and credit lifetime while preserving the execution model's no-early-
  visibility rule and deterministic rollback.
- **Files Modified:** `docs/plans/e4_layout_transform_pattern.md`.

### Decision 3: Treat reshape as metadata-only but not zero-copy

- **Choice:** `RESHAPE` preserves the compact linear byte sequence and requires equal
  element products, while still moving into separately credited L2 storage under a
  distinct layout key.
- **Alternatives Considered:** Temporal identity movement without shape metadata;
  byte-permuting reshape; cross-level aliasing.
- **Rationale:** This gives `BM_RESHAPE_TILE` one testable semantic meaning. Named
  physical operations handle reordering, and cross-level alias lifetime is outside the
  current architecture.
- **Files Modified:** `docs/plans/e4_layout_transform_pattern.md`.

### Decision 4: Include bounded ViT patchify, not general im2col

- **Choice:** E4 patchify is non-overlapping `[C,H,W] -> [Gh*Gw,C*Ph*Pw]`, with only
  deterministic edge-zero padding and one compact batch item per descriptor.
- **Alternatives Considered:** General overlapping/dilated Conv2D im2col; a hidden
  global-memory gather; deferring all patch movement.
- **Rationale:** ViT patchification is a bounded one-source/one-destination map. General
  Conv2D im2col may duplicate source elements and needs E6/E1 address generation. The
  current Conv2D implementation was verified to materialize im2col on the host.
- **Files Modified:** `docs/plans/e4_layout_transform_pattern.md`.

### Decision 5: Make resource fit constructive and partition-specific

- **Choice:** Define conservation for partitioned L3/L2/L1 credits plus reorder bytes
  and transform slots; reserve destination/reorder/slot resources all-or-none; reduce
  requested bursts to the exact bound and refuse a zero bound.
- **Alternatives Considered:** Reusing the current `max(1,min(C3/4,C2/4))` helper;
  reserving resources incrementally; omitting L1/reorder terms.
- **Rationale:** The old helper cannot prove transform progress because it omits byte
  expansion, private storage, transform concurrency, downstream L1 window, and
  partition headroom. All-or-none admission prevents resource wait cycles.
- **Files Modified:** `docs/plans/e4_layout_transform_pattern.md`.

### Decision 6: Require layout identity in TagCAM keys

- **Choice:** Use `{TileID, layout_id}` for source and destination payload identity and
  prohibit duplicate transform requests to a resident or reserved destination key.
- **Alternatives Considered:** Bare `TileID`; allowing the current duplicate path to
  erase the transform flag; using a hash match as correctness evidence.
- **Rationale:** Canonical and transformed bytes for one logical tile must coexist and
  cannot be accepted by the wrong consumer. Reuse is represented by explicit consumer
  references to one completed destination.
- **Files Modified:** `docs/plans/e4_layout_transform_pattern.md`.

### Decision 7: Preserve serialized opcode identity and reject ambiguous legacy forms

- **Choice:** Append new opcode values without renumbering v3, use an explicit v3
  normalization table, and reject legacy reshape, shuffle, opcode/transform mismatch,
  and non-identity AUTO forms that lack a complete descriptor.
- **Alternatives Considered:** Inserting opcodes beside existing BlockMover values;
  trusting raw enum casts; guessing a reshape destination shape; silently dropping AUTO
  transform fields.
- **Rationale:** Existing binary and JSON programs need deterministic decoding. A
  guessed shape or renumbered raw opcode would turn compatibility into silent payload
  corruption.
- **Files Modified:** `docs/plans/e4_layout_transform_pattern.md`.

## 5. Wrong Decisions (CRITICAL)

The initial decision to trust the supplied `kfr` working directory and create the
requested branch there was wrong. The remote and issue state immediately showed that
it was not kpu-sim. The accidental branch was removed, the checkout was restored to
its original detached clean state, and all task work was restarted from a fresh
kpu-sim worktree at current `origin/main`. Lesson: verify repository identity and
remote issue provenance before creating task branches, even when a worktree path is
provided.

The first design draft also incorrectly said `AutoBlockMoverOperands` could not encode
a transform; the struct does declare `Transform`, while the assembler forces identity,
the behavioral AUTO path ignores it, and serialization omits its fields. Direct source
review corrected the inventory. The first envelope draft also subtracted headroom
without first saturating at zero and used total rather than currently idle movers. The
review correction defines saturated `free`, source-reference claims, and `M_idle`.
Lesson: distinguish a declared field from behavior in every execution lane, and make
resource equations safe under the exact integer implementation domain.

No incorrect design decision remained after those corrections.
