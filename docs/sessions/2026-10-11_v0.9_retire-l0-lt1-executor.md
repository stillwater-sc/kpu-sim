# v0.9 Retire the L0 L-T1 Executor (kpu-run-csp-programs Step 4e)

**Date:** 2026-10-11
**Version:** v0.9
**Status:** Complete (4e); step 5 (`--algo` leaves kpu-run) next
**Tests:** 264/264, CLI tests included (274 before: the executor's suite and the L0 L-T1 CLI
tests were removed, see §2)

## 1. Summary

#355 (step 4d.2) was merged, and with it the last user of `TileTransactionExecutor` went. 4e
removes the executor and everything only it fed. L-T1 interprets the CSP program; an L0 program
is a trace and runs at L-B only, as the oracle.

## 2. Decisions

- **An L0 program at L-T1 is refused, not rerouted.** `run_at`, the platform's `run` and
  `step_begin`, and `make_stepper` refuse it the way they already refused L-CA: "an L0 program is
  a trace; L-T1 runs a CSP program (--program file.csp; write one with kpu-csp-gen)". Lowering
  the L0 to CSP behind the caller's back would time a program nobody wrote.
- **The run identity shrinks to what still varies.** `residency`, `stream_digest` and
  `dataflow` were filled only by the executor's inputs. A CSP program states its residency in
  its text, which `program_digest` already covers. The field tripwire test was updated to the
  new arity.
- **Version 3 `.tflow` stays readable; nothing writes it.**
  - The checker's self-test mutates a clean v3 bundle, so one is kept as a fixture:
    `tests/program/tflow/shared_reader_v3.tflow`, the #279 program, written by the executor
    before it went. It passes TF1-TF9, and all 24 self-tests pass on it.
  - `.gitattributes` pins its bytes, because the manifest gives byte offsets into the columns.
- **Shared types moved instead of being duplicated.** `Hop`, `Mover`, `mover_of` and `Cycle` went
  to `program/hop.hpp`, because the record's columns and the ABI's PLACE leg name a leg by them.
  `tile_key` went to `tile_program.hpp`, beside `TileCoord`.
- **kpu-run's L0 path refuses `--streams`, `--timeline` and `--tflow` by name.** A file's STREAMS
  record is carried through `--emit-l0`, so a file written from a file still says what it said.
  The L0 path's device flags now configure nothing L-B models. They leave with `--algo` in
  step 5, which the plan now says.
- **`examples/characterize` is unchanged.** It validates values at L-B and times with the
  analytical `TileDag`, and never ran the executor. The plan had left its fate to 4e. Whether it
  should characterize csp-gen programs is a question about what it measures, not about this
  retirement.
- **CLI tests:**
  - Those that drove L0 at L-T1 were removed where a CSP twin existed: the T4 record, its check
    and binding, the viewer smoke, step and timeline.
  - The T64 binding test moved to a csp-gen program.
  - The three `--streams` tests became one refusal test per retired option.
  - The `--emit-l0-result`-after-agreement contract is now only `kpu_run_csp_emit_result`'s,
    since an L0 run has one level and no verdict to wait for.

## 3. Found while working

- **A stale binary passed the first full suite.** `cmake --build build -- -k` passes a bare `-k`
  to Ninja, which needs a count, so the "keep going" rebuild never ran. My grep for `error:` then
  found nothing, because there was no compiler output. The 273/273 that followed tested the
  kpu-run built before the change. It was caught because `kpu_run_tflow_written` passed against
  a binary that should have refused it. Rebuilt with `-- -k 0` and reran.
- **The real run then failed three tests:**
  - `kpu_run_deploy_from_spec` and `kpu_run_reports_unmodelled_fields` expected two L0 levels.
    Their expectations are now "only one level ran" and "L-B ignores". L-T1's unmodelled fields
    are still asserted, in `test_virtual_platform`.
  - A version-3 record reads back with `op_space == "l0"`, not empty, as the header states. I had
    assumed otherwise in the new test.

## 4. Wrong decisions

- **Reading "no errors" from a filtered build log without checking that the build ran.** A grep
  for errors cannot tell "built cleanly" from "did not build". After a filtered build, check a
  target's timestamp or the tool's tail before trusting the test run that follows.
