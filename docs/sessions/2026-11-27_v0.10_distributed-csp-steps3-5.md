## 3. Technical Decisions

**Decision 1: a result that accumulates expects its merges (#606).**
- `call ... to T at s merges k`: no read of the result runs until its k merges have landed, as the
  Combiner signals a tile ready only after its last merge.
- L-B showed the race without it: a drain took the partial, and the accumulating call then found no
  result.

**Decision 2: one CSP per flow for DMA engines too (#634, CodeRabbit).**
- A DMA engine sends on one channel, as a mover does, so no flow waits behind another's credit.
- Consequence: P1 needs one engine per input edge node, and the 2×2 fixture went to 2 engines per
  controller. It is reversible if engines should serve several nodes.

**Decision 3: the SoC spec is hierarchical (the user, 2026-11-27; #635).**
- **The levels:** SoC → cluster (one spec for every node: an L3 tile and its compute tile) →
  sub-cluster → resource.
- **Ownership:** the BlockMovers belong to the L3 tile, since they drive the NoC and L2 traffic. The
  Streamers and the Combiner belong to the compute tile.
- **Flat fields:** on a mesh they are refused, and derived as views (`derive_mesh_views`), so every
  existing reader works unchanged.
- **The checkerboard stays flat;** it retires with CTE.

**Decision 4: every action has exactly one place, in one process (#634).** An index listed twice
would run twice, one listed nowhere would never run, and each counts once in the action list. The
structure check refuses both.

**Decision 5: P1's schedule.**
- **C:** stationary, block-distributed. After K, it drains north to row 0 and out of its edge port.
- **A** enters at the west edge and moves east; **B** enters at the north edge and moves south.
- **Movers per node:** E, S and N for sends, a and b for feeds, c for the drain.

**Decision 6: P5 holds its copies.** Each node keeps its L3 copy and its L2 copy (`reads 0`); the L3
copy serves its pushes and its feed. The third-input mover `bm.x` carries it.

**Decision 7: the coverage rows are measured, not written by hand (#639).** #617 builds them from the
generated programs, every built class at once.

## 4. Issues Encountered

CodeRabbit found real defects in every round, and each fix has a test that fails without it:
- **#633:** a call staged its inputs and its result in one shared scratch, so an output naming its
  input's tile computed zeros; a repeated operand read a freed slot.
- **#634:** a store counted as use of its channel (D3); held residencies skipped the read count (D4);
  a DMA engine could carry two flows; a capacity rounded down to zero read as unbounded; an action
  listed twice counted once.
- **#636:** totals that wrap 32 bits; vector units compared by presence only; a writer that dropped a
  disagreeing flat edit; adjacent clusters overlapping by a rounding, which led to the floorplan
  tolerance becoming the 1 nm rounding grain.
- **#638:** the help said `--dtype` defaults to fp32, while `--distributed` defaults to int8.
- **#639:** an example command missing `--size` and `--tile`.

CI:
- **#631:** a Windows CRLF checkout broke a test that edits fixtures as text; the samples are now
  pinned with `-text`.
- **#636:** the Windows job hit its 45-minute limit after a header-wide change missed the compiler
  cache; the re-run passed.

## 5. Wrong Decisions

- **A generator branch started on an unmerged branch.** The #606 work was begun on the docs branch and
  had to be moved onto main before its first push.
  - **Lesson:** branch from a freshly pulled main, every time.
- **An enum member inserted mid-list** (`BlockKind::Cluster`), next to a comment saying it was
  appended. Caught before the commit.
  - **Lesson:** append, or say why not.
- **Tests that edited flat fields directly.** After the restructure they had to move to the
  hierarchy.
  - **Lesson:** a test that edits a derived view tests the view, not the spec.
