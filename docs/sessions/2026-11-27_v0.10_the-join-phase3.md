**Date:** 2026-11-27

## 1. Summary

The memory subsystem (Phase 1) and the compute subsystem (Phase 2) run joined on one simulator,
from one CSP program: DRAM → DMA → L3 → BlockMover → L2 → Streamer → array → Combiner → L2 → L3 →
DMA → DRAM (`kpu-run --system`). Nothing is hypothesized: C reaches DRAM from the array, and DRAM ends
with L-B's result bit for bit. The evaluation (`docs/analysis/cycle-prototype-evaluation.md`) covers
where the cycles go and recommends on decision 5.

## 3. Technical Decisions

**Decision 1: the transform is the BlockMover's, through a tile buffer of one L2 slot (3a).**
- A `DenseRows` lane goes as soon as its bytes are in.
- A `DenseColumns` lane (the transpose) waits for the whole tile: its latency is built as state and
  measured (15 beats at 16-byte beats).
- Rationale: memory-hierarchy-roles puts transforms on the write into L2. A transpose needs every
  row before its first column.

**Decision 2: the L3 tile's BlockMover side mirrors the L2's credit routing (3b).**
- A Read is a consumer, and the slot's Release waits for it.
- A Write is a producer, under the slot's credit, which a Release returns to the slot's next
  producer (the DMA engine or the BlockMover).
- The ports take turns between the two sides.
- Rationale: the L2 already worked this way (2d), and it keeps one rule for every buffer.

**Decision 3: one wiring of the compute half (3c).** `build_compute` serves both the stand-in L3 and
the L3 tile, and the summaries' per-component lines are shared functions.

**Decision 4: the join covers single-L3 deployments on a direct link.** NoC deployments are refused.
Joining over the NoC is future work.

**Decision 5: the recommendation on decision 5 is in the evaluation; the decision is the user's.**

## 4. Issues Encountered

CodeRabbit found real defects in every round; each fix has a regression test that failed without it:
- **3a (#599):**
  - a dense Move completed with its padding beats still in flight;
  - the plan's L2 slot could not hold its padded tile (a 1×1 gemm);
  - dense sizes wrapped 32 bits.
- **3b (#600):**
  - a strided Move's per-row reads were refused;
  - a read's bounds were checked by a sum that could wrap (SIGSEGV);
  - a strided Writeback with gaps could never complete;
  - a read inside the slot but past its tile was served.
- **3c (#601):** artifact paths aliased through links:
  - by a directory link, or a link to a file not yet written;
  - through the run directory's own files (counters.json, summary.txt, run.json, run.json.tmp);
  - and `write_counters_json` checked its stream before closing it.
- **Squash merges.** A squash-merged predecessor conflicted with the stacked branch's own copy of its
  commits. Main's tree equalled the predecessor's head, so the stacked side was taken.

## 5. Wrong Decisions

- **The path guard was fixed piecemeal.** The guard against two artifacts naming one file took five
  rounds: a lexical comparison, then links, then run-directory paths, then a link to a file not yet
  written, then each file the run directory writes.
  - **Correction:** one helper, `distinct_artifacts`, over every destination a run writes.
  - **Lesson:** list every file a command writes, and check them all at once, after their final paths
    are known.
- **A test that passed for the wrong reason.** The first wrap test used an unaligned address and passed
  before the fix, because the alignment check caught it.
  - **Lesson:** confirm a regression test fails without its fix, for the reason it names.

## 6. Verification

```bash
cmake --build build -j16 && (cd build && ctest -L "system|compute" --output-on-failure)
./build/tools/csp-gen/kpu-csp-gen --algo matmul --size 64 --tile 16 --dtype int8 --l3 9 \
    --target tests/program/deploy/kpu_s1.json -o /tmp/mm64.csp
./build/tools/kpu-run/kpu-run --program /tmp/mm64.csp --deploy tests/program/deploy/kpu_s1.json --system
```

The int8 64³ at `l3 = 9` takes 6905 clocks and is L3-bound. At `l3 ≥ 16` it takes 5897 clocks,
bound by the BlockMover and the L2 slots. The RTL's 8×8×16 takes 1107 / 723 clocks (0.65×).
