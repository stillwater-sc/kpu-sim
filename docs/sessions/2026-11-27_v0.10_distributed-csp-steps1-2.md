## 1. Summary

Decision 5 was taken: the cycle core replaces `ConcurrentTimingExecutor` (CTE) as L-CA, because CTE
was built on the wrong resource model. The user then set the machine the cycle core must model, and the
order of work:
- **The machine:** the NoC is a push-only, one-hop XY mesh of DMM nodes (an L3 tile with its own compute
  tile). Each node has 8 BlockMovers, and credits travel on a separate network. DMA engines sit on the
  memory controllers, and a periphery ring on the controllers' clock joins them to the mesh's edge ports.
- **The order:** first, show that distributed CSP programs exist for every pattern class under that
  allocation; then rework the NoC; then retire CTE.

Two plans and two steps were merged:
- the plans (#629);
- the machine as a deployment (#630);
- the level-2 program and its text form, `dcsp 1` (#631).

## 3. Technical Decisions

**Decision 1: the machine (the user's, 2026-11-27).**
- **The NoC:** a push-only XY mesh, one hop between neighbours, with no routers. Each node can send 4
  packets and receive 4 at once. Credits travel on a separate network.
- **The movers:** 8 BlockMovers per L3 tile: four sends, three feeds (a, b, and x, a third input stream),
  and one drain.
- **The periphery:** DMA engines belong to the memory controllers, and a periphery ring on the
  controllers' clock joins them to the edge ports. It carries DMA flows only, as a first step.
- **Data-dependent movement:** run-time indices stay at the DMA, so the mesh sees only static patterns.
- **The runners:** R5 deletes the operator-schedule and network runners and the resnet baseline.

**Decision 2: the mesh is its own layout, beside the checkerboard (#630).** `MeshLayout` in
`mesh_layout.hpp` derives the nodes, links, edge ports and ring stops; `ArrayLayout` stays the
checkerboard's.
- Alternative: extend `ArrayLayout`. Its cells, BlockMovers-by-abutting-edge and torus have no mesh
  meaning, so mixing the two would blur both.

**Decision 3: a channel owns its slots, and there is no Release action (#631).**
- **Slots:** each channel lists the receiving pool's slots it owns, so a slot's credit always returns to
  one sender.
- **Reads:** every write that fills a slot states the reads its residency serves. The last read frees
  the slot, as level 1 records the consumers per residency.
- Alternative: a Release action in some process. With several consumers, which process releases is an
  order across processes that a distributed program does not have.

**Decision 4: `dcsp 1` is flat.** Every process lists its actions, with no loops. Generators write the
large programs; the text form is for reading them and for writing the small hand-traced ones.

## 4. Issues Encountered

CodeRabbit found real defects in each round, and each fix has a regression test that fails without it:
- **#630, first round:**
  - an unguarded optional;
  - undeclared memory controllers named by the floorplan but not by the naming map;
  - zero-width DMA engines;
  - imported mesh floorplans not checked against the layout;
  - mesh wires recorded in one direction only.

  It also found a defect older than the PR: both structure producers wrote top-left, while the record
  defines its origin at the die's lower-left, so the viewer drew every model floorplan upside down.
- **#630, second round:**
  - zero-height grid cells;
  - the die's x offset leaking into the record;
  - the SVG reading a mesh port's side from the wrong end of its label;
  - missing CTest labels.
- **#631:**
  - an empty I/O mode passed validation;
  - an action kind could fill the wrong pool;
  - the reader capped numbers by digit count, not by their 32-bit range;
  - a tile-grid ceiling that could wrap.
- **CI on #631:** the Windows checkout rewrote the `.dcsp` samples as CRLF, and a test that edits them
  line by line failed there. The samples are now pinned with `-text`, and the reader is tested on CRLF.
- **A CI infrastructure failure on #630:** a GitHub server error during CMake setup on Windows; the job
  was re-run.

## 5. Wrong Decisions

- **Widening a bound without checking what used it.** Lifting the reader's digit limit to the full
  32-bit range made a ceiling elsewhere able to wrap; the next review caught it.
  - **Lesson:** when a parser accepts larger values, check every arithmetic use of the field.
- **A test that edited fixtures by text, on a platform-dependent checkout.** It passed on Linux and
  failed on Windows.
  - **Lesson:** a fixture a test edits as text is pinned with `-text` from its first commit, as the repo
    already does for the L0 corpus.
