**Date:** 2026-10-15

**Status:** Complete (step 5 of 5, `docs/plans/domain-flow-debugger.md`, #363); stacked on #373 (step 4)
**Tests:** see §6

## 1. Summary

The last step of the domain-flow debugger. When L-T1 runs in the same `kpu-run`, the `.dflow`
record carries its run, joined on the action index:
- every action's legs, in L-T1 cycles;
- each Load whose L3 slot decided its start, and what the wait cost;
- each final tile's proximity to L-B under L-T1.

The viewer shows these in a timing inspector, adds "next slot-bound Load", and can switch its axis
to L-T1 cycles, with every label saying L-T1 and uncalibrated. The record stays L-B's: time lives
only in the overlay's two tables.

## 3. Technical Decisions

- **Decision 1: the overlay is joined, not merged.** L-T1's records keep their own table, keyed by
  the action index the plan names as the join key. L-B's tables are unchanged. D8 still forbids
  time anywhere but `lt1_*`, so an L-B view cannot pick up L-T1's cycles by accident.
- **Decision 2: the slot wait is per Load, from the interpreter.** Step 5a counted slot-bound Loads
  only in aggregate. `Record::slot_wait` stores the same quantity (credit minus every other bound)
  on the Load's record, so the overlay does not re-derive it. L4 checks that the per-leg waits add
  up to the aggregate.
- **Decision 3: per-tile proximity comes from `tile_check`.** `check_tiles` already walked every
  element; `per_tile` keeps each tile's maxima and verdict. Computing them in the recorder would
  have been a second implementation of the bound.
- **Decision 4: the overlay needs L-T1 in the same run.** `kpu-run --dflow` attaches it from the
  L-T1 outcome when L-T1 ran (`--level block-sequential` or `all`); an L-B-only run records
  `lt1: null`. No second run is started for the record.
- **Decision 5: a fixture with slot waits.** matmul at its own L3 is never slot-bound (step 5a), so
  the overlay's waits would go untested on it. The streamed `place = lowest` program from step 5a's
  test is checked in as `tests/program/dflow/streamed_lowest.csp`.

## 4. Issues Encountered

- **The viewer's `int` helper was used before its `const` definition.** The new overlay block in
  `parse` ran before it, a temporal-dead-zone error. Found by reading the order; it is now hoisted
  to the top of `parse`.
- **The viewer did not decode `f64`.** `lt1_tiles` is the first f64 table. Found by the headless
  test.
- **A CMake pattern assumed the wrong output order** (the "wrote" line comes before the run
  summary).

## 5. Wrong Decisions

- The first self-test insertion used an anchor that did not match, so nothing was added. That was
  caught because the run still showed 38 tests; the block was re-inserted.
