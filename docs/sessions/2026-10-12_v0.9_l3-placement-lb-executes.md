**Date:** 2026-10-12

## 1. Summary

L-B's L3 used to be a map from tile name to values, counted against capacity. It is now addressed
storage, `(module, slot) -> {tile, residency, values}`, and L-B executes the address every action
carries (step 2).

- `csp/behavioral.hpp`:
  - a Load, Inherit or opening Writeback writes into the action's slot and tags it;
  - a Writeback into its own residency's slot rewrites it in place;
  - a Move or Store reads the slot, checking its tag; a Release frees exactly that slot; a Retain
    holds it.
  - `held(L3)` is the number of tagged slots. `resident_at(tile)` gives a tile's address.
- Refused at the action (`BehavioralError`), naming the slot and both tiles:
  - a write into a live slot;
  - a read or release of a slot holding another tile (#279's class of defect);
  - a release of a free slot, and a residency never released (named at the collision it causes, or
    at the program's end);
  - an action with no address, a slot outside the program's L3, a bank that is not `slot % banks`.
- `L3Geometry{slots, banks}` (`csp_program.hpp`), from a compiled program (`l3_geometry(CspProgram)`)
  or its text (`lang::l3_geometry(Program)`). Every L-B caller passes it: `csp_run.hpp` (the
  reference and the level run), `csp_step.hpp`, and L-T1's value interpreter (slots only).
- `CspStep::place`; `kpu-run --step` prints `@ l3[0]:5/b1` after each placed action.

## 2. Decisions

- **The bank check against the deployment is deferred to step 6** (the user, 2026-10-12). The
  deployment specs declare `l3.banks = 4` and every existing program defaults to `banks = 1`, so an
  equality check now would refuse every corpus program run with `--deploy`. The check lands when
  banks enter L-CA's timing, with the programs updated. Recorded in the plan's step 6.
- **A slot is tagged with its residency as well as its tile.** A Writeback carries no "opens"
  flag; the residency distinguishes rewriting a resident tile (same residency) from writing over a
  live one.
- **Free slots are not stored.** The L3 state is a map of tagged slots, bounded by the slots in
  use, so a large L3 costs nothing until it fills.
- **A context `add`'s vector is found by its tile.** A `Stage` carries no address, so L-B looks the
  vector up through its tile index. The vector's residency is checked live by the walker; giving
  stages an address can come with the trace's L3 ops (step 4) if the replay needs it.
- **L-T1's value interpreter checks slots, not banks** (geometry `{l3, 0}`): it has the capacity
  but not the program's banks. L-T1 executes placement itself in step 5.
