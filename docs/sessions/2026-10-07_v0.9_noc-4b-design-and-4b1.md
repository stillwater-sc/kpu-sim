- Writeback is still a DMA read: step 3's push vocabulary exists only at L-T1.

executor mapping, the floorplan's engine-to-port wiring as data, the ADR comparator, and a
T4/T16/T64 matmul oracle against the L0 reference.

## 3. Technical Decisions

**Decision 1: The attachment is read back from the floorplan, not re-derived.**
- The rule depends on the generated geometry (controller and port positions).
- Re-deriving it would put a second copy of the rule outside `generate_floorplan`.
- Reading the Attach links keeps one rule, and leaves the floorplan's JSON and digest unchanged.

**Decision 2: An explicit engine-to-controller map, not a changed default.**
- Round-robin stays the default, so no hand-built config changes timing.
- Only `csp_config_from` sets the per-controller numbering.

**Decision 3: The builder states what it does not map.**
- The spec's rates (bytes per cycle) and the executor's rates (GB/s and latencies) are different
  vocabularies.
- `l2.banks_per_tile` is an L-T2 bank count, not tile-sized L2 buffers.
- Mapping either would invent a calibration, so the builder lists them in `unmapped` instead.

**Decision 4: The oracle also holds bit-identity.**
- ADR D5 sets the bar for the cycle-accurate level: `atol` plus `rtol` against L0.
- `fill()`'s inputs keep every product and partial sum exact, so the CSP result is bit-identical,
  and the test holds that too.
- A later step that changes bits has therefore changed the arithmetic, not the timing.
