## 1. Summary

Before Phase 2, the user asked for the debug and visualization pattern. Two plans were written and merged:
- `docs/plans/cycle-mflow-and-debug-server.md`, the record, checker, viewer and read-only server;
- `docs/plans/kpu-debug-server-full.md`, browser-started runs behind OAuth through a Cloudflare Tunnel.

Steps 1–7 of the first plan were then implemented, each through the CodeRabbit loop and merged:
- a cycle-core run now writes a `.mflow` record;
- `mflow_check.py` checks it, including the transaction rules `trace_validator.py` checked;
- the memory-side debugger draws it, through a shared reader;
- a loopback server serves runs and viewers to a laptop over an SSH tunnel.

The new checks found a real controller bug, fixed in its own PR.

## 3. Technical Decisions

**Decision 1: retire the Chrome DRAM trace.**
- **Choice:** the user's call. Move its checks to `.mflow`, then retire it (step 11).
- **Alternatives considered:** keep it beside `.mflow`.
- **Rationale:** M5 already checked more timing, and against the declared device. The transaction checks moved as M9–M11. Nothing else needed the format.
- **Files:** `tools/trace/mflow_check.py`, `patterns/memory/lpddr5/INVARIANTS.md`.

**Decision 2: the recorder observes; the components report.**
- **Choice:** a null-by-default `MemoryEvents` sink, called at the moment each event happens.
- **Alternatives considered:** polling state every cycle, or writing a file per component.
- **Rationale:** polling misses intra-cycle events; files would be another format with no checker.
- **Check:** recording changes nothing; a test compares the summaries with and without it.

**Decision 3: the readers follow a version bump in the same PR.**
- **Choice:** the record's readers (`read_mflow`, `mflow_check.py`, the viewer) learn version 4 in step 2 itself.
- **Rationale:** each refuses an unknown version. The M1 window split and the Fill exemption moved from step 4 into step 2 for the same reason.

**Decision 4: the read-only server serves viewers under `/view/<name>/`, and the shared reader under `/view/common/`.**
- **Rationale:** a page's relative `../common/mflow.js` then resolves with no rewriting.

**Decision 5: Fills and waits are required only of fixtures that promise them.**
- **Choice:** `test_viewer.py --expect-fills --expect-waits`.
- **Rationale:** a valid cycle-core run may have neither.

## 4. Issues Encountered

**M1 failed on the first cycle-core bundle (step 1).**
- **Symptom:** 17 bursts in flight against a window of 16.
- **Root cause:** the engine's reads and writes each have a window of 16, but v3 records one window.
- **Fix:** step 1 recorded the true combined bound; v4 records both windows, and M1 checks each.

**A use-after-free in the recorder (CodeRabbit, #561).**
- **Symptom:** the record read wrong clock values; the tests had passed by luck.
- **Root cause:** the recorder kept pointers to the run's domains, which are destroyed when `run_memory_subsystem` returns.
- **Fix:** it copies them. A regression test fails deterministically without the fix.

**The controller's starvation loop (M10, #576).**
- **Symptom:** one burst served by 16 ACTIVATEs and 16 PRECHARGEs in `kpu-memsim`'s T4 run.
- **Root cause:** a starved younger read closed the row of an older write. The write was held off by tRTW, won the reopen, and the read starved again.
- **Fix:** a starved request closes only from younger pending hits. A controller test shows 20 reopenings before the fix and 1 after.
- **Also found:** M10 then needed to allow a page closed for a refresh before its CAS; 9 such cases in the T4 bundles, all followed directly by a REF.

**tWTR_L across an intervening read (CodeRabbit, #578).**
- **Root cause:** M5 copied the controller's adjacent-CAS rule, but tWTR_L runs to every later read of the write's bank group.
- **Fix:** M5 now applies the full rule, and every bundle passes it.
- **Controller:** the same gap is unreachable today, because tWTR_S plus a burst is at least tWTR_L. Filed as #579.

**`kpu-run` review findings (#575).**
- **Symptom:** `--memory-mflow .` would have emptied the working directory, because the bundle's destination was removed before rewriting.
- **Fix:** the destination is guarded; artifact paths inside the bundle are refused; every write is checked.

**Debug server findings (#582).**
- **Symptom:** symlinked manifests could publish metadata from outside the root; a test fixture named `<script>` failed on Windows; Windows `\r\n` changed a fixture's byte count.
- **Fix:** all fixed, with tests that fail on the old code where that is possible.

**Defensive hardening from review rounds.**
- `mflow_check.py`: malformed `run.json` and `counters.json` are refused as unreadable (exit 2), never crashes.
- `mflow.js`: a served bundle's file names resolve against its directory's path.

**`cr-ondemand.sh` could not tick CodeRabbit's box once.**
- **Symptom:** GitHub returned HTTP 500 to the comment edit.
- **Fix:** none needed; the included review was used instead.

## 5. Wrong Decisions

**The plan claimed M6 was free, and that the timing table lacked tWTR and tRTW.**
- **Why wrong:** M6 is round-robin fairness, and the table already had both. Written without reading the checker and the bridge.
- **Correction:** the plan was corrected in step 1.
- **Lesson:** read the code a plan cites before writing the plan.

**The plan's M6 ("waits never overlap") assumed one cause per cycle.**
- **Why wrong:** the engine records several causes in a cycle.
- **Correction:** M7 is per cause.

**The first Fills/waits viewer tests demanded them of every cycle-core bundle.**
- **Correction:** they're required only behind fixture flags (Decision 5).

**A test comment named the wrong issue (#577).**
- **Correction:** fixed before review.

**The changelog and session log were deferred after step 1, "to go with step 2", and slipped to the end.**
- **Lesson:** write the wrap-up when promised, or say plainly that it is batched.
