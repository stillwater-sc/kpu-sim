# v0.10 The Combiner's Per-Channel Scale (#427)

**Date:** 2026-11-16
**Version:** v0.10
**Status:** in review (PR). #427 stays open.
**Tests:** see §5.

## 1. Summary

The requantization scaled a whole tensor by one multiplier and shift. Quantized layers scale each
output channel by its own, so #427 listed "a per-channel scale" as not built. It is built now:
`scale(qm[j], qs[j]) @ combiner` reads each column's multiplier and shift from two int32 vectors,
and every level computes it.

## 2. Technical Decisions

- **Decision 1: multiplier and shift per channel** (the user's choice, 2026-11-16). Both are
  int32 vectors, as TFLite's per-channel requantization has them.
  - Alternative: per-channel multipliers with one shared shift. Its shift is always valid, but
    synthesized multipliers would still saturate everything, so it buys little.
  - Consequence: the values come with the inputs. A synthesized int32 vector spans the whole
    range, so its shifts are invalid. The run is refused where a shift is first used, naming the
    stage and the value, and a CLI test pins that refusal.
- **Decision 2: the vectors are a stage's operands, as an add's bias is.** They are resident in
  L3 and as wide as the result tile.
  - L-B reads them from L3.
  - L-T1 counts both as stage reads for their Releases.
  - At L-CA, `VectorStage` carries a second vector (`arg2`, `read_seq2`, `arg_loads2`), and the
    three places that number, wait for and retire an add's read do the same for both.
- **Decision 3: a new L0 op, `REQUANT_CHANNELS`** (opset 1.9.0), not inputs on `REQUANT`. An
  older reader would parse `REQUANT` with inputs it does not know, drop them, and scale by its
  defaults, silently. A new op it refuses by name: the rule `opset_for` states.
- **Decision 4: the parser tells the forms apart by the token after `(`.** A name starts the
  vectors; a number, or a minus sign, starts the integers.
- **Decision 5: the generator keeps qm and qs resident where a linear keeps b**: with B's panel
  under OS, with the last K block under WS, around each final merge under IS. It needs two more
  L3 slots.

## 3. Issues Encountered

- None beyond the expected refusal of synthesized inputs (Decision 1).

## 4. Wrong Decisions

- None.

## 5. Verification

```bash
build/tests/program/test_csp_requant
(cd build && ctest -R requant_channels)
```

- On OS, WS and IS, at L-B, L-T1 and L-CA, against a reference computed in the test: the int32
  matmul plus the bias, wrapped, requantized per column, then relu. The channels' values differ,
  so a level that read the wrong column's, or column 0's for all, would fail.
- The trace: `REQUANT_CHANNELS in=qm:0,0;qs:0,0`, at opset 1.9.0. It is written, read back and
  replayed bit for bit. A shift of 63 is refused.
- The refusals, in the walker and the validator: one vector; an int8 vector; a tensor in a
  vector's place; vectors not resident. The text round-trips.
