# Session: the timed levels write their own domain-flow records (#402, part 1)

**Date:** 2026-11-17
**Version:** v0.10 (in progress)
**Issue:** #402 (part 1 of 2: L-T1 and L-CA events; part 2 is `dflow_diff.py`)

## 1. Summary

`kpu-run --dflow-lt1` and `--dflow-lca` write a timed level's run as a `.dflow` 6.2 record. It holds
L-B's steps, the level's events with their cycles, and the level's own final values. The format
gains a slotted L2, accumulator and array edge (6.2), and the identity key gains the position's
program line. L-CA's Releases are now timed at their credit return, not their handover.

## 2. Technical Decisions

- **Format 6.2, a slotted L2 (the user's choice, 2026-11-17).** Format 6 made a timed record declare
  L2 and the accumulator by banks and rows, which no kpu-sim level models, so no BLOCK_MOVE, STREAM,
  COMPUTE or DRAIN could be written. 6.2 adds `{"modelled": true, "slots": N}`. The alternatives
  were declaring the RTL's rows from the deployment's `systolic` block, which claims geometry no
  level models, or writing DRAM and L3 events only.
- **No row events (the user's choice).** L-CA moves each tile whole, at its process's rate. Rows
  derived from that rate would be arithmetic, not something L-CA observed. They come with a level
  that models rows (#388, #401).
- **One builder for both levels** (`record/timed_record.hpp`). L-T1's legs and L-CA's matched legs
  (`timing/csp_records.hpp`) are the same `Record` form. The events mirror the RTL sample's
  (`dflow_rtl_sample.py`): the same tokens after a Load, a Move and a Drain, the same credits after
  a Feed, a Drain and a Release. That is what lets part 2's diff join them.
- **The identity key names the program line.** LU's `laswp A[k, j]` and `trsm_ll(A[k, k], A[k, j])`
  both move A[k, k] at the same (k, j), so their keys collided (E2). The line makes the key finer,
  never coarser, so every record that passed E2 still does, the RTL samples included.
- **Two things the format can't say are counted, not hidden.**
  - A store frees its slot at its ejection, into the DMA engine's buffer. The format has no layer
    for that buffer, so the Release's credit is stamped at the store's end.
  - A tile the Combiner reads in place never leaves L3 in a transaction, so its credit is left out.
  - The record's `not_modelled` gives both counts.
- **A timed record needs every step.** A cut or refused L-B record is refused by name.

## 3. Issues Encountered

- **L-CA's Releases were stamped at the driver's handover.** `csp_records` timed a Release at its
  handover, before the BlockMover had retired the entry. The first L-CA records had 50 to 80 more
  E4 re-stamps than stores, which is how it showed. The executor already logged the real return
  (`CREDIT_RELEASED`), but the same event type marked L3 and L2 credits. Each site now tags its
  pool, and a Release takes its tile's next L3 credit. Afterwards the re-stamps equal the stores
  at both levels. The new test fails 180 of 185 assertions without the fix. The bubble report reads
  these Release legs too.
- **L-CA can't run the RTL sample's program.** Its matrix is named L, and L-CA maps matrices onto
  A, B and C. Part 2's join against the RTL sample needs a program L-CA runs.
- **The domain-flow viewer refused 6.2.** It now reads it. It names the level and the cycles to
  result, and says the events aren't drawn yet.

## 4. Wrong Decisions

- **Local suites without Node.** The domain-flow viewer's data-layer checks run only with Node on
  the PATH. My local runs skipped them and reported 364/364, so CI was the first to see the timed
  L2-accumulator record fail. The fault was older than #469: the test's replay never learned the
  L2 accumulator's partials (#455, #456), and no L2-accumulator record was in its bundles until now.
  Fixed in the test, with L-B's L2-accumulator record added too. Lesson: run the suites with Node
  (`~/.nvm/.../bin` on the PATH), and read the skip count, not only the pass count.

- I first wrote the CHANGELOG's Fixed heading in the middle of the Unreleased Added list, so later
  Added entries sat under Fixed. Moved to the end of the section.

## 6. Part 2: `dflow_diff.py`

- **The key in both records' terms.** A tile is its operand name and coordinates, a process and a
  layer their names, a loop its variable's name, so the key is the same across producers. A layer
  whose address form differs (slots against rows) is joined without its addresses, and the report
  says so. If that makes two of one record's events share a key, it refuses rather than guess.
- **Divergence** is per matched event: its start, and its duration. The first divergence is the
  earliest, in A's cycles, beyond `--tolerance`. The largest are reported too.
- **The done-when, met.**
  - The RTL sample is renamed A, B, C (`dflow_rtl_sample.py --names`). Tiles refer to operands by
    index, so only the manifest and the program text change.
  - L-CA's record of the renamed program joins every one of the sample's 26 transactions and all
    56 of L-CA's events. The sample's 56 row events are one-sided, each under a joined transaction.
  - The diff names the first divergence: the first load's DMA, start −1 and duration −2.
  - Its largest start divergence is real: L-CA frees B[0,0]'s slot at 23, when its last Move out of
    L3 ends, because its Release follows that Move in program order. The hand-written sample frees
    it at the program's end.
- **Tests:** `test_dflow_diff.py`, 7 cases. A record joins itself; a shifted event is the first
  divergence, and isn't one within the tolerance; an event of another identity is one-sided on
  each side; L-T1 joins L-CA on every event and diverges; the sample joins L-CA across L2's two
  forms; a record with no events, or one that fails the checker, is refused.
