# v0.9 The Linear Operator at L-B: CSP-Language Step 2 (Epilogue Ops, Vectors, Tile Contexts)

**Date:** 2026-10-09
**Version:** v0.9
**Status:** Complete (step 2); step 3 (the vector processor at L-CA) next
**Tests:** test_csp_linear 8/8 (new); test_csp_language and test_l0_serialization updated; full
suite in the PR

## 1. Summary

The linear operator, Y = act(X . W + b), is the language's fusion case. Its epilogue (a bias and
an activation) can run in the compute fabric, on the streamer's drain, or on the BlockMover's
egress. Where it runs is the program's decision, written as a **tile context**, and the machine
decides whether a site can run it at all.

Built:
- the L0 epilogue ops, with reference kernels;
- the derivation;
- `vector` operands;
- the unfused epilogue as calls;
- `via` contexts through the walker, the symbolic validator, the IR, the behavioral interpreter
  and the printer;
- per-site vector units in the deployment spec, with placement checked against them.

## 2. Decisions

- **One set of element functions.** `activate()` and `bias_tile()` serve the L0 kernels and every
  context stage, so a fused epilogue is bit-identical to the unfused one by construction, not by
  test luck. The transcendental forms evaluate in double and round once. On one host every level
  agrees bit for bit; across hosts libm may differ in the last bit, which is why ADR 0001 D5
  gives gelu, silu and atan a tolerance.
- **A vector operand is a one-column tensor,** tiled down its column (the parser's existing
  `vector` form). `b[j]` is tile (j, 0). An add's vector must be tiled as the result's columns.
  That operand-level rule is shared by the walker and the validator, so the two cannot disagree
  on a trailing tile.
- **A stage belongs to the action that moves the tile past its place:** `fabric` and
  `str.drain` to the Drain, `bm.egress` to the Writeback. Stages must be listed in path order,
  because the order the tile meets them is the order they apply.
- **The opset bumps to 1.1.0 and the format does not.** An older reader already refuses an
  unknown op by name, so no file is silently misread. `act=` is required on ACTIVATION: an
  activation without its function has no meaning, so it is not an ignorable attribute.
- **The OPSET line records the ops the file uses** (`opset_for`), not the build's opset: 1.1.0
  only when a file contains BIAS_ADD or ACTIVATION. This is the same content-based rule
  MIN_CONSUMER follows. A matmul or LU file is byte-identical to before, so the checked-in
  corpus and the loadable fixture did not need regenerating.
- **Placement is checked only against a target.** Values do not depend on placement, so a
  target-free compile accepts any known place. `compile`, `validate` and `ActionStream` take a
  `Target`, built from a device by `target_from`.
- **Decided in the build and flagged for review:**
  - The fabric's operations are fixed at {add, relu}, which is what `execute_matmul` builds today.
  - `bm.ingress` is refused for a result: it is an operand's way in, and operand contexts are a
    later step.
  - The emitter refuses the epilogue ops: L0 does not say where the epilogue runs, so the
    emitter has no basis to choose.
  - A stage's bias is read from L3 at L-B; its delivery and its time are step 3's.

## 3. Verification

- The element functions match independently computed values (gelu, silu and atan at 1e-6).
- L0's linear operator matches a double-precision direct computation within ADR rtol 1e-4, for
  all four activations. The checked outputs fall on both sides of zero.
- `BIAS_ADD` / `ACTIVATION` serialize and reload. The reloaded program computes the same bits.
  A missing or unknown `act` is refused.
- The lowered L0 (L3 8 and 64) runs at L-B bit-identical to the reference. `kpu-run --algo
  linear` agrees at block-sequential (L-T1).
- 12 written placements and the unfused program (four activations) are bit-identical to the L0
  reference, through both the trace and the stream:
  - each activation at `str.drain` and at `bm.egress`;
  - relu in the fabric;
  - gelu split fabric / bm.egress, and atan split str.drain / bm.egress.

  Symbolic totals equal the traced ones, and the printed program compiles to the same actions
  and contexts and is a fixed point. Unfused costs exactly 16 more loads and 16 more stores (the
  second DRAM round trip of C).
- Placement:
  - `atan @ bm.egress` against S1 with a BlockMover unit lacking atan is refused by line, by the
    walker, the validator and the stream.
  - `atan @ str.drain` runs and computes the reference.
  - `gelu @ fabric` is refused.
  - A machine with no streamer unit refuses `@ str.drain`.
- `movers.vector` round-trips through JSON with the same digest, and an unknown op is refused.

## 4. Wrong Decisions

- **I first wrote the build's opset (1.1.0) on every file's OPSET line.** That changed the bytes
  of every L0 file, and the full suite caught it: `test_l0_corpus` and `test_loadable` compare
  against checked-in files. Lesson: a version written into an artifact describes the artifact.
  The repo had already stated that rule for MIN_CONSUMER, and I did not apply it here.

- **The new test first read the S1 spec by a relative path without `WORKING_DIRECTORY`.** The
  timing tests set it and the program test did not. It failed rather than skipped.
- **I counted the store's line in the test source wrong (13 vs 14)** in three expectations. The
  tests caught it.
- **I first tested the stream's placement refusal with a single `next()`.** The misplaced store
  is many actions in, so the stream must be drained to reach it. A stream reports an error when
  it reaches it, which is its design, not a defect.
- **I first wrote in the plan that the operator runs at L-T2.** kpu-run's resource-transactional
  level is not implemented (#283), so I corrected the claim to L-B and L-T1 before committing.
