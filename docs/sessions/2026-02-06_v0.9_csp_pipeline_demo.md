## 1. Summary

Created an educational demonstration program that visualizes CSP credit/debit flow and
TagCAM operations for a minimal matmul workload. The demo shows the complete dataflow
path through the KPU memory hierarchy:

```
DRAM → L3 → L2 → Compute → L2 → L3 → DRAM
 DMA   BM   STR   (mul)   STR   BM   DMA
```

## 2. Motivation

The previous session fixed DMA concurrency and DRAIN compute dependency bugs, but the
Chrome trace visualization had limited resolution for understanding the CSP synchronization
mechanisms. A transaction log format was needed to clearly show:

- Credit pool state changes (acquire/release)
- TagCAM operations (insert/match/invalidate)
- Dependency tracking (fed_tiles, compute_result_tag_cam)

### Key Design Decisions

1. **Minimal Workload**: 1×1×1 matmul (single tile of A, B, C) keeps output manageable
2. **Transaction Log Format**: Shows cycle, component, event, tile, credit flow, TagCAM action
3. **Stall Filtering**: Default mode hides stall events; use `--verbose` for full output
4. **Educational Annotations**: ASCII diagrams explain credit pools, TagCAM, and dependencies

## 5. Key Observations Demonstrated

1. **Credit Flow Pattern**
   - DMA acquires L3 credit BEFORE starting load
   - BlockMover acquires L2 credit BEFORE starting move
   - Credits released when tile is consumed/moved downstream

2. **Tag Matching Pattern**
   - BlockMover stalls until DMA inserts tile in L3 TagCAM
   - Streamer stalls until BlockMover inserts tile in L2 TagCAM
   - DRAIN stalls until COMPUTE inserts result in compute_result TagCAM

3. **Credit Conservation**
   - Initial credits: L3=4, L2=4
   - Final credits: L3=4, L2=4
   - Every acquire has a matching release

## 8. Bug Fix: COMPLETE Event Timing

**Issue:** The initial demo showed LOAD_COMPLETE at cycle 0, before LOAD_START completed.

**Root Cause:** `TimingEvent::duration_event()` creates Chrome trace compatible events
where `cycle` = start time and `duration` = length. For the transaction log, we need
the actual completion time.

**Fix:** Modified `EventAnalyzer::analyze()` to compute completion time as
`event.cycle + event.duration` for COMPLETE events:

```cpp
bool is_complete_event = (event.type == EventType::DMA_LOAD_COMPLETE || ...);
if (is_complete_event && event.duration > 0) {
    entry.cycle = event.cycle + event.duration;  // Actual completion time
} else {
    entry.cycle = event.cycle;
}
```

**Additional Fix:** Sort log entries by corrected cycle, with START events before
COMPLETE events at the same cycle for logical ordering.
