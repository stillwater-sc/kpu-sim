# Session 2026-11-14: weight- and input-stationary programs, and the Combiner's merge (#430, #429)

## Context

The user's order for v0.10.0: #430, then #427, then #425, each through review and merge. #430
(`kpu-csp-gen --dataflow os|ws|is`) needs #429's accumulate operation, and #429's tests need
#430's programs. The two are one change, so this PR delivers both: the merge of partials in the
language, the trace and every level, and the WS and IS programs that use it. #429's rename
merged as #431.

## Decisions

1. **The L2 accumulator is a language construct: `acc T in l2 { ... }`.** It mirrors
   `acc ... in fabric`. T may be a slice, `C[:, j]`. The block reserves an L2 slot per tile as
   it opens, from the same `l2 = N` the stage blocks use. Each call `+->` into one of its tiles
   drains a fresh partial with a merge mode: overwrite for the tile's first call, accumulate
   after. The store writes the slot back. Alternatives considered:
   - a `+=>` call form that names a resident L2 tile. It has no block to scope the slot, and
     it hides where the slot is held.
   - staging C (`stage C[..] in l2`). That stages a copy of a resident L3 tile, which a partial
     is not.
2. **The slot is reserved at the block's open; the staging id is assigned at the first merge.**
   The trace's stagings must open in action order, and a stage Move inside the block (the
   stationary tile's) comes before C's first merge.
3. **One L0 op, `MATMUL_MERGE` (opset 1.5).** It computes the partial from zero, then overwrites
   or adds, in the tile's number system, through the `merge_tile` helper that L-B also uses. So
   the replay is bit-identical to L-B. Recording the call as `MATMUL_ACCUM` into C would not be:
   it rounds as one sum, not as partial-then-merge. The op carries the partial's L2 slot, so the
   replay checks the slot as it checks a staging's.
4. **The stationary operand is held by an L2 staging** (`stage B[k, j] in l2 { for i ... }`).
   It leaves L3 once per reuse loop, and is fed from its L2 copy. Holding it in the PEs, so it
   is never re-fed, is a weight-stationary array model, which is #427's (and #425's view). Here
   each merge's gemm is timed as a one-call output-stationary chain at L-T1 and L-CA.
5. **WS makes A's column panel and B[k, j] resident inside the k loop**, not B's column panel
   for the whole j iteration. That needs L3 = tiles-per-panel + 1. Each B tile still leaves DRAM
   once. IS is the transpose: B's row panel and A[i, k].
6. **Deferred to #427, refused by name:**
   - an epilogue on the final merge (the store of an L2 accumulator takes `@ bm.egress` stages
     only);
   - an `init` on an L2 accumulator;
   - a late store or a retain of one.
   `lang::print` refuses a program with an L2 accumulator, because the block's open emits no
   action. `lang::format` prints it.
7. **L-CA:**
   - A merge's gemm is a `partial` compute. It starts from zero, and waits until the tile's
     earlier drains have landed, so a partial never overwrites one still in the array.
   - `schedule_merge` times the merge as one add on the Combiner.
   - Overwrite claims the slot at its turn with an L2 credit. Accumulate merges into the entry
     already there and takes no credit.
   - The partial's Writeback is `l2_held`: it leaves the slot.
   - The L2Release waits for the tile's drains and writebacks.
   - A machine with no `combiner` block is refused at L-CA, and by the language on that target.
8. **The ISA path's `CombinerOperation`** (#429's "room for scaling and block formats") gets:
   - a merge mode, with Accumulate built as a read-modify-write through an L2 read;
   - `scale` and `CombinerBlockFormat` (MXINT8, MXFP8) fields, reserved and refused unless they
     are the defaults.

## Results

On the 64³ matmul in 16-tiles (4 × 4 × 4 calls):
- Each stationary tile is Moved 16 times, against 64 for the streamed operand and for both
  operands under OS.
- 64 Drains merge into 16 partials, 48 of them read-modify-writes.
- L-T1 counts 48 × 1 KiB read back and 64 × 1 KiB written by the merges.
- WS and IS match OS per tile at L-B, in fp32 and in int8 → int32 (exact).
- L-T1 and L-CA match L-B bit for bit.

## Wrong decisions

- Two expectations in the refusal test were wrong:
  - a 2 × 2 C fits `l2 = 4`, so the empty block is refused for "no call", not for capacity;
  - with one slot taken by a stage, the capacity error names C[1,1], not C[1,0].
  The code was right in both cases. Lesson: count the slots before writing the expected message.
- The first int8 comparison used `==` on the operands' float storage. The int32 words read as
  NaN there, so bit-identical results compared unequal. The tests now compare bits (`memcmp`).
