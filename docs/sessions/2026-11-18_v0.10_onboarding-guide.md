# Session: an onboarding guide for new developers

**Date:** 2026-11-18
**Version:** v0.10 (in progress)

## 1. Summary

The user asked whether a document on-boards a new developer. None did:
- `docs/02-simulation/simulator-architecture.md` explains the pipeline but not the vision or a
  learning path.
- `README.md` (January 2026) and `README_dev.md` (August 2025) predate the CSP program stack.
  Neither mentions the levels, `kpu-csp-gen` or the `.dflow` records.

New: `docs/ONBOARDING.md`, linked first from both READMEs.

## 2. Technical Decisions

- **Point, don't repeat.** The guide links to the architecture document, the execution model,
  the ADRs and the record spec rather than restating them, and says the linked document wins on
  a disagreement.
- **The design rules as rules.** Section 2 states the ideas a newcomer is likely to get wrong
  (one program at several levels, values at every level, credits not caches, deliberate reuse,
  placement as behavior, streams from the array's edges, the shared record, kpu-sim writing the
  traces), each as a rule whose breach is a bug.
- **No numbers in the walkthrough.** Makespans and bubble counts change with every timing
  change, so the steps say what to look for, not what values to expect.
- **`examples/` called out.** It still builds, but most of it exercises component APIs from
  before the CSP stack; the guide says so.
