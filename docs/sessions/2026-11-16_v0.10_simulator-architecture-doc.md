# v0.10 The Simulator's Architecture Document

**Date:** 2026-11-16
**Version:** v0.10
**Status:** in review (docs-only PR).

## 1. Summary

The user asked whether a document explains the simulator's architecture and how it works. None
did, current and end to end. ADR 0002 holds the model, `fidelity-framework.md` the levels and the
plans the history. The one walkthrough, `docs/architecture/program-execution-uml.md`, had marked
itself out of date since 2026-10-11. This PR adds `docs/02-simulation/simulator-architecture.md`
and retires the UML document.

## 2. Technical Decisions

- **Decision 1: one document for the path, with its code.** Each stage names the headers and the
  classes that implement it, so a reader can go from the diagram to the code. The decisions stay
  in the ADRs, which it links instead of repeating.
- **Decision 2: retire, not redraw, the UML document.** Its class diagrams described an L-T1
  executor and an L0-centred stack that are gone. A redraw would be a second description of the
  same path, to keep in step with the first. It moves to `docs/archive/superseded/` behind a
  pointer, and ADR 0002's checklist entry says where it went.
- **Decision 3: a Mermaid diagram.** GitHub renders it, and it stays text in the repository.

## 3. Verification

- Every path and symbol the document names exists on `main`, checked by a script over the
  document's list.
- The claims about each level were checked against the code. For example, L-T1 computes its
  values with an L-B interpreter (`TransactionalInterpreter::values_`).

## 4. Wrong Decisions

- None.
