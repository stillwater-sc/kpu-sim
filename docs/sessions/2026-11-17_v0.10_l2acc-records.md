# v0.10 The Record Checkers Know the L2 Accumulator (#455)

**Date:** 2026-11-17
**Version:** v0.10
**Status:** in review.

## 1. Summary

Found end to end on 2026-11-16, while assessing what the viewers need to validate CSP programs: a
program with an L2 accumulator, `acc C[:, j] in l2 init D[:, j]`, which every
`kpu-csp-gen --dataflow ws|is` program has, failed both record checkers. Every level agreed on
the values. The checkers predated L2 accumulators (#429/#430), and the records could not tell
them apart from a staged copy. The records now carry it, and the checkers check it.

## 2. Technical Decisions

- **Decision 1: the records carry the partial; the checkers do not guess it.** A checker could
  infer a partial from its first step being a Drain. But the records are shared with the RTL
  (ADR 0005), and an inference written into a checker is a rule no producer agreed to. So the
  record says it: `l2_staging.partial` and `.merges`, and `steps.merge` in `.dflow`;
  `l2_residency.partial` and `.merges` in `.tflow`. The viewers (#456) need the same columns.
- **Decision 2: optional columns, not a version or a minor revision.** Version 6's minor
  revisions are for new transaction layer pairs and geometry forms. These columns change no
  meaning for a record without them (written before L2 accumulators existed, so it has no
  partials), and every reader already ignores columns it does not know. The C++ readers gain
  `read_col_or`, and the checkers type-check an optional column when present. Documented in
  `docs/plans/shared-tile-flow-record.md`, "Optional columns".
- **Decision 3: a rule of its own, S5, for the partial's life**, rather than widening S2. S2 keeps
  the address checks (now allowing a partial's Drains and Writeback). S5 checks the life: opened by
  an overwrite, accumulated into, written back once, never fed, merges counted.

## 3. Issues Encountered

- A `rm -rf $S/$n` in a scratch loop was blocked by the safety check (an unguarded variable). The
  directories were new, so the loop needed no removal.

## 4. Wrong Decisions

- None.

## 5. Verification

- 18 generated programs check clean under both checkers: os, ws and is; no init, bias and bias row;
  fp32 and int8 (12 with an L2 accumulator). Before the change, every ws and is one failed.
- `tools/trace/test_l2acc_checks.py` (CTest `l2acc_checks_selftest`, on the fixture
  `csp_l2acc.dflow`/`.tflow`):
  - the clean records pass;
  - each S5 rule, broken in a copy, fails under S5;
  - a staged copy with merges fails S2;
  - each TF13 partial rule fails under TF13;
  - a copy without the columns fails as before, so the columns are what tell.
- `test_domain_flow_record` and `test_tile_flow_record` ([l2acc]): the fields are recorded and
  round-trip, and a record without the columns reads as no partials.
- Full suites, `release-werror`, gcc and clang.
