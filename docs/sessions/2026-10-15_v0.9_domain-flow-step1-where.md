Step 1 makes each L-B step a readable CSP state transition. The walker reports where in the
program it emitted each action (the statement's line, and every enclosing loop's index and bound).
`CspStep` at L-B now names the process that acted, the channels the tile moved between, the
residency it opened, closed or retained, whether the slot was pinned, and every channel's
occupancy. `kpu-run --step` prints them. This is the state the `.dflow` record (step 2) will write.

## 3. Technical Decisions

- **Decision 1: the walker records `line_` in `enter()` and reads the loop frames in `emit()`.**
  Every action is emitted while a leaf statement is entered (an `acc` block's close emits nothing),
  so the statement being entered is the action's statement. `acc` frames are not loops and are
  skipped. *Alternative:* pass the line through each `emit` call (30-odd call sites); rejected as
  noise.
- **Decision 2: `Where` holds loop variable names as strings.** An `Emission` can outlive the
  stream that made it (it is copied into `CspStep`), so pointers into the AST could dangle. Loop
  names are short, so the copies are small-string-optimized.
- **Decision 3: Upfront counting stays the default.** `VirtualPlatform::step_begin` and kpu-run
  keep printing "N actions" before stepping. `Count::Lazy` is there for the recorder, which must
  not pre-walk (plan §3.5). `CspStepper::size_known()` (default true) and the platform cursor's
  passthrough say which applies.
- **Decision 4: one action of lookahead, with walker errors deferred.** Without a count, the stepper
  learns a step was the last only by pulling the next action, and the values must be final at the
  last step (as before). Pulling ahead would surface a walker refusal one step early (or in the
  constructor), so the error is held and thrown by the step that owns it (tested).
- **Decision 5: `l3_held`/`l2_held`/`cf_held` kept beside `held[]`.** L-T1's replay fills only
  `l3_held`, and kpu-run reads the three. Removing them is churn outside this step.
- **Decision 6: `from`/`to` only for the six kinds that move a tile.** `csp::from_chan` returns
  `Cf` by default for Call, Release, Inherit and Retain, which would draw a move that did not
  happen.
