# v0.10 A Reduction's Dataflow, Stated in the Program (#395, step 1)

**Date:** 2026-11-17
**Version:** v0.10
**Status:** in review. #395 continues: step 2 (L-T1's timing per dataflow, and the `.tflow`
record), and L-CA with #401.

## 1. Summary

Nothing in a CSP program said which operand the systolic array holds. So every level treated a
reduction as output-stationary, even when `kpu-csp-gen --dataflow ws` had already written a
weight-stationary data movement. The dataflow is now part of the program, stated on the
accumulator, with a deployment default, and the `.dflow` record carries it.

## 2. Technical Decisions

- **Decision 1 (the user's, 2026-11-17): on the accumulator, with a deployment default.**
  `acc C[:, j] in l2 dataflow ws`. Every gemm into that accumulator uses it, so one reduction
  never mixes dataflows. Unstated, `fabric.dataflow` applies (os when undeclared).
- **Decision 2: ws and is need `in l2`.** In the RTL (systars systolic-tile.md), a stationary
  dataflow's partial sums leave the array south after every command, so they must be merged
  outside it. An in-fabric accumulator is output-stationary by construction. Both checkers refuse
  the combination, with the fix in the message.
- **Decision 3: `fabric.dataflow`, not `systolic.dataflow`.** The spec's `systolic` block
  describes which modes the RTL tile builds (#396), not a program's default.
- **Decision 4: a two-step split.** Step 1 (this PR) is the program and its record, at L-B.
  Step 2 is L-T1's timing per dataflow together with the dataflow in `.tflow`, so that no
  `.tflow` record says "ws" for a run timed as os.
- **Decision 5 (the user's): L-CA waits for #401**, the cycle-accurate tile, since its fabric
  has one MAC-rate latency for every dataflow.

## 4. Wrong Decisions

- **A fabric accumulator took the deployment's default.** The walker stamped `Default` on an
  unstated fabric accumulator, and a test asserted it ("the deployment's applies"). Under a
  `fabric.dataflow: ws` deployment, an in-fabric reduction would then claim to be weight-stationary,
  which the walker refuses when it is stated. Step 2's L-T1 tests found it. Fixed: a fabric
  accumulator is always `OS`; the default is for an L2 accumulator that states none. Lesson: a
  default needs the same refusals as the value it stands for.
