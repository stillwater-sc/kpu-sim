## 1. Summary

Merged NoC step 4b.4 (#331), then built DRAM plan step 3. A DMA engine now decomposes each tile
into DRAM bursts and keeps up to W in flight; the hosted controller takes bursts and reports
each completion. The plan's test row holds. One engine with W = 32 saturates the controller,
and 32 engines with W = 1 do not. But the cause is locality, not Little's law alone: both
configurations have 32 bursts in flight. Recorded in the plan.

## 3. Technical Decisions

**Decision 1: The engine owns the tile; the controller sees bursts.**
- This follows the plan, §3.3.
- The controller's tile path stays for W = 0, so every existing config keeps its timing.

**Decision 2: The engine emits the tile-level DMA_*_COMPLETE.**
- In window mode the controller never sees the tile, so the engine reports its completion,
  spanning its first burst to its last.
- Completion runs through the same `finish()` as the tile path, so NoC routing (4b.4) and
  store retirement (4b.2) are unchanged.

**Decision 3: Measure before asserting.**
- §1.2 sizes the window by Little's law. Its test row (1 x 32 saturates, 32 x 1 does not)
  looked inconsistent with that law.
- A sweep showed the row is right, for locality reasons. The plan now says so.
