## 1. Summary

I worked through the seven recommendations from the morning's `examples/` inventory (#497–#503).
Each landed as its own PR. The examples that printed values the runtime never computes now say
so. The ones that crashed or silently passed now check their results and run under CTest. Dead
code, binaries and cache-model tools are gone. `examples/program` now shows the program stack
end to end. Along the way, `kpu` turned out to swallow every program's stderr, which hid a crash.

The user then asked why there are 122 open issues, and what is on the critical path to the
simplest program: a matmul on one systolic tile, consistent at L-B, L-T1 and L-CA. Values already
agree at every level, int8 → int32 exact included. Timing is the gap. Seven issues on one piece
of work (#401) are the critical path. The user set the target to int8 → int32 and made L2 bank
concurrency part of the first test.

## 3. Technical Decisions

**Decision 1: docs and cleanup PRs merge on green CI, without a CodeRabbit review**
- **Choice:** the user's instruction, applied to #504, #508, #509 and #521, which carry
  `@coderabbitai ignore` in the body. CI is never bypassed. Code PRs keep the full loop.
- **Rationale:** save the review allowance for code. Recorded in memory.

**Decision 2: an example on a frozen engine goes with its engine, not before it**
- **Choice:** #500 lists the dependents in #266. Each engine's deletion PR deletes or ports them.
  The one exception is `run_matmul_DEPRECATED`, which nothing depended on.
- **Alternatives:** delete them all now. That would leave nothing showing what those engines
  did until the replacements cover it.

**Decision 3: retire the `l3_*` tools rather than rewrite them**
- **Choice:** delete the analyzers and `l3_scheduler`, the only cache model behind them. The cache
  model inside `L2TileScheduler` became #510: `kpu-kernel-compiler` uses it, so it's out of an
  examples PR's scope.
- **Deferred:** the `ReplacementPolicy::LRU` argument in the two kept demos. Dropping it would
  only hide the library's default, so it goes with #510.

**Decision 4: fix the `kpu` stderr filter in place, as a reader thread**
- **Choice:** forward each record from a daemon thread to the saved fd as it arrives. Keep
  dropping NNPACK lines, and forward overlong records whole.
- **Rationale:** the old filter read the pipe only at exit and wrote what it read back into the
  same pipe. Every program importing `kpu` lost its stderr, and one writing more than 64 KB
  blocked forever.

**Decision 5: the first slice is an OS int8 → int32 matmul, with L2 concurrency in it** (the user's)
- **Choice:** #401's acceptance covers:
  - values exact at every level;
  - the fabric from the deployment (#458);
  - the RTL wavefront (#385);
  - L1 stream buffers and the OS drain (#389);
  - L2 slot credits at L-T1 and L-CA (#387);
  - L2 sustaining two vectors per array clock from 250 MHz banks under a 1–2 GHz array (#495);
  - int8 moved as 1 byte (#415);
  - L-T1 within a stated tolerance of L-CA.
- **Rationale:** L2 concurrency is how the design feeds the fabric, so the first timing test must
  include it.

## 4. Issues Encountered

- **The stale module behind #502's error table.** An old `stillwater_kpu` from 2025-12 sat at
  `build/src/bindings/python/Release`, and the four kernel scripts put that path first. Against
  the current module they all pass. The issue's "no longer bound" errors came from the stale one.
- **The legacy `tools/python/stillwater_kpu` package** falls back to a NumPy
  `MockNativeModule`, so five scripts "ran" while simulating nothing. They were deleted, and the
  package is #512.
- **`model_compatibility.py` exited 1 with no text.** Two bugs: `ModelTestResult` was built without
  `status`, and the stderr filter hid the `TypeError`.
- **The walker's L2 placement includes per-call copies** that the timed levels run unplaced. The
  placement check compares only the program's stagings (`!a.copy`), as
  `test_csp_lca_place.cpp` does.
- **CodeRabbit** was rate-limited on #520, and its silent clean reviews again had to be confirmed
  from the summary's "between X and HEAD" range. One on-demand review ($0.50) was requested
  within the $2 cap.

## 5. Wrong Decisions

1. **#513 took five CodeRabbit rounds on one rule.** I added a 64 KB bound to the filter. Its edge
   cases came back four times: `\r` records, an overflow fragment that starts with NNPACK, the rest
   of an overlong record, and a record completed just past the bound. **Lesson:** a bound added to
   answer a minor finding is new behavior that needs its own specification. Write all its cases
   and tests before the first push, or don't add it. (The user's `pr-cadence` rule: stop on minor
   edge cases.)
2. **I first called #495 "second, after #401".** The design feeds a 1–2 GHz array from 250 MHz L2
   banks, so L2 concurrency is part of the first timing test, not a later performance pass. The
   user corrected it, and #401's acceptance now includes it.
3. **I claimed in the assessment that #503 might cover the examples graded Review.** It adds
   program-stack examples instead. I corrected that before filing #514.
4. **A test that couldn't fail.** The first version of
   `test_unterminated_output_is_forwarded_while_running` passed on the old code, because the
   reader thread kept appending after the join timed out. I caught it by running the test
   against the old code, and fixed it with a snapshot taken before the child was released.
   **Lesson:** run every regression test against the old code before trusting it. That rule held
   for every other test today.
5. **A `gh pr comment -q` that failed silently** (`|| true`) and dropped my outside-diff reply on
   #513 until I checked. **Lesson:** don't mask the exit status of an outward-facing call.

## 6. Verification

- Every regression test added today was run against the code before the fix, and fails there:
  - the `TrackingAllocator` and `ResourceManager` tests;
  - the exception-safety test;

- `program_run_levels --placement` was run on every corpus program and the L2-staged matmul, on
  `kpu_s1` and `kpu_t4`. Every level agrees with L-B and executes the walker's slots.
- An int8 → int32 64³ matmul is exact at L-B, L-T1 and L-CA, and its L0 trace replays bit-exact.
  Its 98304 DRAM bytes confirm #415: the int8 operands move as 4 bytes.
- Full gcc ctest: 382/382 on #513's branch, 378/378 on #520's (cut from main before #513 merged). The CI matrix (ubuntu gcc and clang, macOS clang, Windows
  cl) passed before every merge.
