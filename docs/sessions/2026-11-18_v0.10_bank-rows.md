# Session: L-CA's banked L2 in its records (#401, slice 1, second PR)

**Date:** 2026-11-18
**Version:** v0.10 (in progress)
**Issues:** #401 (slice 1's second PR), #402 (its last item: L-CA row progress)

## 1. Summary

The bank calendar keeps each L2 transfer's booking when L-CA keeps its events: its tile, client,
start, and each row's clock and stalls. Three consumers read it:

- **The timed record:** L2 in the rows form, an event's L2 address its first row, and the
  transfer's rows as row events (BM_ROW, STR_ROW, DRAIN_ROW).
- **`csp_records`:** each leg's bank wait.
- **The bubble report:** a new cause, "L2 bank ports".

## 2. Technical Decisions

- **L2 and accumulator addresses are placement, not identity** (the user's choice, 2026-11-18). A
  banked L-CA record and an RTL record both declare L2 by rows, but each producer places tiles in
  L2 its own way, so their rows differ for the same transfer. §5.3 leaves those addresses out of
  the key, keeping L3's and DRAM's, which the program places. `dflow_diff` reports differing L2
  rows on matched events as placed differently. The viewer joins the same way, and E2 checks
  uniqueness with the same key.
- **A row event is row r of its transfer, beat 0**, at the clock the bank served it, inside its
  transaction's time. A transfer with more L2 rows than its tile has rows gets none (E3 places a
  row inside its tile), and the record counts those.
- **Bookings match legs by tile, process, start clock and direction**, the leg's start being the
  clock the transfer booked at. A drain's booking start is after its epilogue, but its leg start is
  the drain's own.

## 3. Issues Encountered

- A booking had to name its tile as the program does, so the driver, which holds the executor's
  tile-to-coordinate map, attaches it to each booking. Naming operands by matrix letters would have
  been wrong for any operand but A, B and C.
- **A banked record lost every unstaged Feed's L2 credit** (128 on the linear program), caught by
  the full suites (`dflow_diff_selftest`). The builder read "no L2 address" as "not staged", and a
  banked L2 gives every transfer an address, its first row. It now reads the step's own staged
  flag. `test_bank_rows` compares a banked record's Feed credits with a slotted one's, and fails
  with the old check.
- Two record tests still assumed L-CA's slotted L2. The format self-test now checks the rows form
  and runs its slot-form cases on the accumulator. The L-T1/L-CA join test now expects L-CA's row
  events to be the only one-sided events, each under a matched transaction.

- CodeRabbit's review of #476 (15 findings, all valid). Fixed:
  - **Rows past a fixed-size L2's end** (the major one): addresses now wrap at the L2's rows, in the
    banks' order (`Geometry::row`, shared by the calendar and the builder).
  - **Staged-copy releases** had no address in a banked record; they now name the copy's first row.
  - **Row events' lanes** were always 0; they now take their transaction's lane.
  - **Bubble cause:** a ready Feed held behind a bank-stalled Drain is now blamed on L2 bank ports.
  - **Bank waits** are matched only to legs that started.
  - **The placement report** counts each matched event once.
  - **The reader** refuses a rows-form L2 without row-mod-banks.
  - The rest were docs and test tightening.

- CodeRabbit's second review (7 findings, all valid). Fixed:
  - **Bubble cause:** stalls the Combiner's longer work overlaps no longer blame the L2 banks. A
    leg's `bank_delay` is the clocks its stalls added to its finish, clipped for a drain
    (`L2Banks::overlap_last`); `bank_wait` stays the raw count.
  - **`dflow_diff` exit:** a placement-only difference now exits 1.
  - **Reader:** refuses an L2 declared both by slots and by rows.
  - **Builder:** refuses a row count the record cannot hold; the rows form follows the geometry,
    not the bookings.
  - **Docs:** when placement is compared; a transaction's first row vs each row event's row.

- CodeRabbit's third review (7 findings, all valid; a nitpick on a line this PR does not touch
  was left). Fixed:
  - **Bubble cause:** a bank-delayed result ahead is the cause only if it still held the operand
    when the operand was ready.
  - **Writeback:** its bank delay is clipped by the egress unit's overlapping time, as the
    drain's is. No run-level regression: the bm.egress program tried never stalls a writeback on
    its banks.
  - **Reader:** refuses a rows-form L2 with a zero dimension.
  - **Spec:** three fixes.
  - **Tests:** the mixed-form test asserts its message.
- `occupancy_viewer`'s browser-load check failed once under the parallel gcc run and passed three
  times alone: the headless browser timing out under load, not this change.

- CodeRabbit's fourth review (9 findings, all valid). Fixed:
  - **Bubble cause:** a bank-delayed result ahead is the cause only when the operand took the
    lane it freed (started within a clock of its finish); a Move whose source Writeback was
    bank-delayed names the banks.
  - **Driver:** a run restores the executor's L2 log mode, on any exit.
  - **Reader:** refuses L2 dimensions outside 32 bits.
  - **Docs:** the CHANGELOG, the spec, and the diff self-test's usage and fixture checks.

- CodeRabbit's fifth round, on `6132744` (3 inline findings, 1 outside the diff, 1 follow-up;
  all valid). Fixed:
  - **Bubble cause, lane:** a bank-delayed result ahead is the cause only on the operand's own
    lane.
  - **Bubble cause, Move after a Writeback:** the Writeback's bank delay is the cause only if its
    finish set the Move's ready.
  - **Reader test:** each bad row count is confirmed written, and matched by name.
  - **Spec:** L1's PE-array exception; a key collision is the producer's to avoid, and E2 and
    `dflow_diff` report it.
- My bubble regression first missed the Move case: its Move started after its ready, so the walk
  took the in-order branch. It now starts at its ready, and fails without the fix.
