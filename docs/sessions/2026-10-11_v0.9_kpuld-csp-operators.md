# v0.9 Loadables Run CSP Programs (kpu-run-csp-programs Step 4d.2)

**Date:** 2026-10-11
**Version:** v0.9
**Status:** Complete (4d); 4e (retire the L0 L-T1 executor) next
**Tests:** test_orchestrator (9 cases), test_reservation (9), test_orchestration_mmio (10),
test_loadable (17), all migrated to CSP operators; full suite in the PR

## 1. Summary

Step 4d's second half: orchestration runs CSP programs. A `.kpuld` operator carries its CSP
program, with its trace's L0 only as the oracle. `KpuDevice` runs chains of them and holds what
one program retains until another inherits it. Residency is the programs', so the deciding
orchestrator decides admission only: it issues RESERVE and LAUNCH.

The chains measure what they should:
- Three GEMMs with a gap need 5 L3 slots cold and 9 warm. Holding W across the middle operator
  costs exactly its four tiles.
- The warm two-GEMM chain loads exactly 4 fewer DRAM tiles than the cold one.
- `relu_then_bias` keeps H = relu(X W) in L3, never stored by its producer. The bias operator
  inherits it, and the H it stores equals the two oracles composed, at L-B and L-T1.

## 2. Decisions

- **The decider issues RESERVE and LAUNCH only** (decided 2026-10-11, as recommended).
  - A CSP program loads its own tiles, so a PLACE would be a DMA no program sequences. The
    device refuses one by name. PLACE comes back with L-T2 (#283), where descriptors order the
    legs inside a run.
  - Three things retire with it, each of which only made sense while the decider held tiles:
    - release at last read;
    - `reuse_shared_inputs`;
    - the greedy-prefetch ablation with reservations off.
  - Reuse is now measured by comparing two loadables: the same chain written with
    `retain`/`inherit`, and written without.
  - Alternative: keep PLACE as a prefetch that turns into an implicit inherit. Rejected, because
    the decider would then sequence a DMA, against "the CSP program is the only sequencing
    source".
- **The program's declared L3 is its need** (decided 2026-10-11, as recommended).
  - An operator reserves `l3` less the slots it inherits, which are already held.
  - The device refuses when that does not fit beside the other held tiles.
  - The plan had said the orchestrator rewrites `l3` to the free slots. Rewriting would make a
    program's text, identity and timing depend on the chain around it, and its reservation
    would be "everything free", which stops reserve-then-launch.
- **Binding by declaration, not first use.** `inputs` bind to the operands declared `in` or
  `inout`, `outputs` to those declared `out`. The program states what each operand is, so the
  device infers nothing. An operand whose shape or tiling differs from its tensor's is refused,
  so a tile index means the same region in every program that touches the tensor.
- **The device keeps retained tiles' values, and DRAM changes only where a program stores.**
  - A level's result is DRAM with the retained tiles laid over it (4d.1). Copying whole
    operands back would therefore put an unstored retained tile into the TensorStore, which is
    a write the program never made.
  - So the device writes back stored tiles only, and holds retained tiles' values itself.
- **The chain is checked when the device is built**, by tensor tile:
  - every inherit has a retainer;
  - every retain has a claimant;
  - nothing loads a retained, unstored tile's stale DRAM copy;
  - no tile is retained twice;
  - tilings agree.

  The first operator to fail is marked invalid, and the orchestrator refuses on reaching it, as
  it already did for a program that does not parse.
- **Format 2.0.0 refuses 1.x after the min_consumer gate.** A file demanding a newer reader is
  then refused for that demand, whatever its container version. The 1.x golden file is kept
  (renamed `_v1`) as the evidence of the refusal. The hand-built `needs_a_newer_reader.kpuld`
  had its `format_version` patched (one byte), so the min_consumer gate stays the only one that
  can refuse it.
- **`csp_program` is required by the reader, not by `(required)` in the schema.** A schema-level
  `(required)` would make the verifier reject a 1.x file as a broken buffer, before the reader
  could refuse it for its version.
- **MMIO ABI 2.0.**
  - `MAN_L3_SLOTS` reuses `MAN_PEAK_LIVE`'s offset with a new meaning, hence the major bump.
  - `MAN_LIST` selects which tile list the existing read window shows, rather than adding three
    windows.

## 3. Found while testing

- The migrated suites passed when run from the repository root, but under ctest three failed:
  `relu_then_bias` reads its programs from `tests/program/csp/`, and those suites ran in the
  build directory. They now run with `WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}`, like the other
  suites that read fixtures.
- Each new claim was then checked against a number that would differ if it were wrong:
  - the 5/9 minimum L3;
  - the 4-tile saving;
  - H all zeros in DRAM between the two launches, then the composed oracle;
  - each chain refusal by its message.

- **Review (CodeRabbit, PR #355): dirtiness was judged from unordered sets.** A retained tile
  counted as clean if the program stored it at any point. So a tile stored, written again and
  then retained looked clean: an intervening load of its stale DRAM copy would pass, and DRAM
  would receive the later value at write-back.
  - The fix: dirtiness is tracked in program order, so a write sets it and a store clears it.
  - The one shape still wrong, stored then written then retained, is refused with the reason:
    a level reports the retained value, not the stored one. It stays refused until a level
    reports the value at each store. A test covers it.
- **Review: ADR 0003 still stated the old contract** in D4 (PLACE moves the bytes), D5 (the
  manifest, ABI 1.0) and §5 (6/10 slots). Amendment notes were added beside each.

## 4. Wrong decisions

- **Judging a retained tile's dirtiness from unordered "written" and "stored" sets** (found in
  review, fixed above). I had noticed the store-then-write edge while writing it and moved on.
  It should have been refused or handled then, not left implicit.
