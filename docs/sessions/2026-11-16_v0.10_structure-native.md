# v0.10 The Structure Record, Written Natively by the Model (#392)

**Date:** 2026-11-16
**Version:** v0.10
**Status:** in review. #392 continues: the esg sync issue, the `.dflow` block-id link.

## 1. Summary

`kpu-floorplan --structure <out.json>` writes the structure record, `kpu-structure` v1, from the
floorplan, with no conversion step. `structure_diff.py` compares two records block for block.

## 2. Technical Decisions

- **Decision 1: the native writer is the converter, ported.** `floorplan_to_structure` follows
  `structure_from_floorplan.py`'s model branch line for line: the same die root, block order,
  kinds, roles and layers, and the same NoC network and node order. One record, two producers
  of it, so the CTest can hold them equal. Only the provenance differs: the native one names the
  build and keeps the layout and the floorplan's digest in `details`, and has no `from`.
- **Decision 2: the equivalence is a CTest, not a golden file.** `structure_native_t4` regenerates
  both records from the same `kpu-floorplan` run and diffs them, so a change to either side that
  the other lacks fails at once. A golden file would only catch a change to one.
- **Decision 3: a general comparer, `structure_diff.py`**, rather than a test-only one. ADR 0005's
  promise is that a model record and an RTL record of the same configuration can be compared,
  and a mismatch is a bug in one. Blocks, networks, nodes, links and channels match by id;
  numbers within a relative tolerance; provenance is not compared.
- **Decision 4: the deployment's digest is not claimed.** The plan's `configuration_digest` is
  the deployment digest, and `SocFloorplan` does not carry it. The record carries the
  floorplan's own digest under `details.floorplan_digest` instead of mislabelling it.

## 3. Issues Encountered

- **The model's and the RTL's records do not compare yet.** Every id differs: the naming map's
  `t4/l3[0]` against the RTL's instance path. The schema already has `resource` for the naming
  map's name; the RTL must fill it, and the comparison must key on it. Recorded in the plan
  (§5.2) and as part of the esg sync issue.

- **The v0.9.0 tag broke two byte-for-byte tests on every fresh build** (this PR's CI after the
  tag, and `main` too). The build takes its version from the latest tag, and the writers stamp it:
  - `test_l0_corpus`: the corpus `.l0` files say `PRODUCER kpu-sim 0.8.0`. That line names the
    build, not the format (KPUL0, MIN_CONSUMER and OPSET do), so the three comparisons now mask
    the producer's version (`unproduced`) and stay byte-exact everywhere else. A release no longer
    fails them.
  - `test_loadable`: its `.kpuld` is meant to fail on a version change, by its own comment, so it
    was regenerated. Two bytes changed, both version stamps (`producer_version` 8 → 9 at 0x38, and
    the embedded L0 text's PRODUCER line). The README now says every tag needs this, right after
    the tag.
  Both found by reconfiguring locally after the tag (version.hpp is generated at configure time,
  so a build configured before the tag still said 0.8.0 and passed).

- **CodeRabbit's review: three findings, all valid.**
  - The die's id, `<device>/die`, could also be a block's name in an imported floorplan, which the
    record would then duplicate (and make its own parent). `validate_floorplan` refuses the name.
    Test.
  - `structure_diff.py` used `--rel` as the absolute tolerance too, so at `--rel 0.01`, 0.005 and
    0.01 compared equal. A separate `--abs` (default 1e-9 mm). Test.
  - The viewer README's native command wrote a file the next command did not read.
- **The second review (on-demand, 1.50 USD): one finding, valid.** Refusing `<device>/die` in
  `validate_floorplan` broke import compatibility: a version-1 floorplan with such a group no
  longer imported, even for `--json` or `--svg`. The check moved to `floorplan_to_structure`,
  which throws `FloorplanError` (kpu-floorplan `--structure` reports it and exits 1); the
  floorplan still imports and draws. Test: it validates and round-trips, and only its record is
  refused.

## 4. Wrong Decisions

- A self-test check that compared a record with a "round trip" whose string replace was a no-op:
  it tested nothing. Removed before commit.

## 5. Verification

- `test_floorplan` "the floorplan as a structure record": over the T64, one record block per
  floorplan block plus the die root; unique ids; one root; every parent a block; rects in mm;
  resources kept; one NoC network whose links' ends are its nodes; deterministic.
- CTest `structure_check_native_t4` (the native T4 record checks clean) and
  `structure_native_t4` (it is the converted record, provenance aside).
- `structure_check_selftest`: the comparer finds nothing between a record and itself, or a copy
  with other provenance or reversed blocks. It names a moved rect, a changed kind, a dropped
  block and a dropped link by their paths.
