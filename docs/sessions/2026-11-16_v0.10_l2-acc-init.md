# v0.10 An L2 Accumulator's Init, through the Combiner (#427)

**Date:** 2026-11-16
**Version:** v0.10
**Status:** in review (PR). #427 stays open.
**Tests:** see §5.

## 1. Summary

A fabric accumulator takes an init: `acc C in fabric init D`, a bias tile or row streamed in from
an edge. An L2 accumulator, which the WS and IS schedules use, refused one: "its first merge
overwrites its slot". So a WS or IS matmul could not compute C = A . B + D, and the generator
refused `--init` under those dataflows. Now the Combiner adds the init on each tile's first merge.

## 2. Technical Decisions

- **Decision 1: the Combiner adds the init on the first merge** (the user's choice, 2026-11-16).
  The slot is written with partial + X, the Combiner reading X from L3 as it reads a bias vector.
  - Alternative: the BlockMover preloads X into the partial's L2 slot, and every merge
    accumulates. It needs no new Combiner input, but a move cannot broadcast, so a bias row would
    not work.
- **Decision 2: the trace keeps the first merge an overwrite, then `MERGE_INIT`.** The replay
  checks an L2 accumulator's slot, and the first merge is the one that opens it, as an overwrite.
  So the add is a separate op after it: `MERGE_INIT` (opset 1.10), Y += X. X is a tile tiled as
  Y, or a vector broadcast down its rows, in Y's accumulator type. One op covers both shapes, and
  it runs before the final merge's epilogue when the first merge is also the last.
- **Decision 3: at the levels, the init is a stage.** `VeOp::Init` goes first on the first
  merge's Drain. The language has no spelling for it: the walker puts it there. Every level
  already handles a stage that reads a vector from L3:
  - L-B adds it to the merged value;
  - L-T1 counts the read for X's Release;
  - L-CA (`VectorStage::AddInit`) numbers, waits for and retires the read as it does an add's.
- **Decision 4: X must be resident at the `acc` statement**, in the validator and the walker
  alike, and still resident at the first merge (the walker). The shape and type checks are the
  fabric init's: the walker's are now one function (`check_init_shape`), shared by both kinds of
  accumulator.
- **Decision 5: `init C` (C += A . B) stays refused** for an L2 accumulator, with the reason. The
  walker refuses an L2 accumulator whose tile is resident in L3, and reading C into its own
  first merge needs that residency to hand over. A fabric accumulator does it already.

## 5. Verification

```bash
build/tests/program/test_csp_acc_init
```

- WS and IS, x `init bias` and `init bias-row`, x fp32 and int8, at L-B, L-T1 and L-CA, checked
  against a reference computed in the test:
  - fp32: init + A . B, within the proximity bound, because the init joins the reduction at a
    different point;
  - int8: the plain int8 matmul plus the init, wrapped in int32, exactly.
- The trace: one `MERGE_INIT` per C tile, at opset 1.10.0. It is written, read back and replayed
  bit for bit.
- The refusals: an init that is not resident, or not in the accumulator's type, and the
  generator's `--init accumulate` under WS.
