# v0.10 Distributed CSP programs: the generators P6–P9, P4, and the coverage report Decision Log

**Date:** 2026-11-28
**Version:** v0.10
**Status:** Complete; the coverage report's answer is with the user before the NoC rework
**Tests:** 569/569 (gcc), 563/563 (clang), on the coverage branch

## 1. Summary

Steps 5 and 6 of `docs/plans/distributed-csp-programs.md` (epic #603) are done. Every operator
pattern class, P1–P9, has a level-2 CSP program on the DMM mesh, written by a generator. On the 1×1,
2×2 and 4×4 meshes, every program passes D0–D4, runs on L-B without deadlock (D5), and gives its
operator's values (D6).

The coverage report (`docs/analysis/distributed-csp-coverage.md`) is measured from the programs. It
answers the plan's first requirement: the one-hop mesh, with eight movers per node and a DMA-only
periphery, covers every class. No class needs the allocation changed.

## 3. Technical Decisions

**Decision 1: P7 needs no credit waits on L3 deliveries, so it cannot deadlock (#644).**
- Each mover sends in the order of a synchronous one-hop-per-step schedule, and each tile delivered
  into L3 gets a slot of its own.
- The cost is L3: 11 of 16 slots on the busiest 4×4 node, and the count grows with the side. The
  report carries it.
- CR pointed out that row 0's pushes out to the DMA engine can still wait for its store buffer. The
  docs now separate that wait, which always ends, from the deadlock argument.

**Decision 2: an intermediate is a `temp` operand (#645).**
- P8's T is neither loaded nor stored, so `in`, `out` and `inout` all misdescribed it.
- `temp` has no DRAM values. The structure check refuses any load or store of it, except as a
  gather's or scatter's tile.
- Alternative: declare T `out` and never store it. Rejected: the program would say T leaves the
  nodes.

**Decision 3: P8 is fp32 throughout (#645).**
- The GEMM kernel's inputs share one number system, so the second GEMM's T must be in D's.
- An int8 → int32 first GEMM would need an int32 × int32 MAC.

**Decision 4: P9 orders its steps at the DMA engine (#646).**
- A column's engine runs step s's loads, then its stores, then step s + 1's loads.
- So a window re-reads, after its store, the position the program appended. The test checks that from
  step 1 on.
- This is also the decode's real order.

**Decision 5: run-time indices are a DMA load's or store's, never the mesh's (#647; plan §7
decision 2).**
- `load G[i,j] gather E by idx` and `store Z[i,j] scatter W by jdx` are the new forms.
- The mesh moves only the `temp` tiles G and Z, in a static pattern.
- CR found that the default inputs could make an index negative, so `kpu-csp-check --run` could never
  pass a generated P4 program. Index vectors now default to rows of what they index, and an end-to-end
  CTest covers it.

**Decision 6: the coverage report is measured, and kept current by CI (#617).**
- `csp/distributed_coverage.hpp` reads every number off the program, nothing off the generator.
- `kpu-csp-coverage --check` fails when the report's block is stale.
- The verdict rules are written in the report: needs, fits at a cost (with the numbers), fits.
- The periphery ring model is stated as a hypothesis: N PHYs evenly spaced, every tensor interleaved
  over them, the shorter way round.

## 4. Wrong Decisions

- **The P9 work was written on the P8 branch** while #645 was open. Caught before staging: it was
  stashed and restored onto its own branch from main after #645 merged. Lesson: branch before writing,
  even while waiting on a review.
- **The first draft of P9's north flow had inconsistent slot counters**: per-step counters that did not
  follow the arrival order. It was rewritten before any test ran, with each node's north flow defined as
  its own tiles then the row below's whole flow. The sender's and receiver's counts then agree by
  construction.
- **P8's first full suite failed `test_csp_distributed`.** It pinned the operand-kind refusal's old
  wording. The full suite caught it, and I fixed the test text rather than the behaviour.

## 5. Validation

- Every generator's tests run on 1×1, 2×2 and 4×4: D0–D4, D5 on L-B, and D6 against an independent
  reference, compared word for word.
- `test_csp_distributed_coverage`:
  - the measures agree with P7's own cost record;
  - P5's reach is 6 hops on the 4×4, with nothing forwarded;
  - P2's interior node runs 8 movers, 4 of them sends.
- `csp_coverage_report_current`: the report's block matches the programs. Tested by editing a number
  and watching the check fail.
- Full suites on the coverage branch: 569/569 (gcc), 563/563 (clang).

## 6. For the user

The report's answer, "every class fits", is what the plan says goes to the user before the NoC rework
(#618) starts. The costs to weigh:
- store-and-forward through nodes that only pass tiles on;
- P2 at all 8 movers on an interior node;
- P7's L3 cost growing with the mesh's side.
