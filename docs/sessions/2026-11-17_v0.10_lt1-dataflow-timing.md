# Session: L-T1 times each dataflow by the RTL's rules (#395, step 2)

**Date:** 2026-11-17
**Version:** v0.10 (in progress)
**Issue:** #395 (step 2 of 2; step 1 is PR #465)

## 1. Summary

L-T1 timed every accumulator's gemm chain as output-stationary. Now a weight- or input-stationary
call (an `acc ... in l2 dataflow ws|is`, or one that states none under a deployment whose
`fabric.dataflow` is ws or is) is timed by the RTL's schedule rules (systars
`docs/architecture/systolic-tile.md`):

- PRELOAD: R clocks (R = `fabric.pe_rows`), whatever K is.
- The stream: S rows (ws: M rows of A; is: N columns of B).
- The partial sums leave south: `last = in1 + W − 1`, `out1 = last + R`.
- The compute tile is busy `R + max(S, R)`, so the next PRELOAD waits for the previous stream to leave.

The records carry the dataflow. The checkers validate each dataflow's formulas, and the CLI and
both viewers name the dataflow.

## 2. Technical Decisions

- **A stationary call is a chain of one.** Each call's partial sums leave the array, so there is
  no chain to pipeline. This matches the L2 accumulator, where each Drain is a merge.
- **The stationary tile, not C, must fit.** ws holds B's K x N; is holds Aᵀ's K x M. K is the
  call's macs over M·N. A stationary tile larger than the array stays one leg ("stationary tile
  larger than the array").
- **The south edge has no link rule.** The OS top-link rule (TF14, P5) applies to OS chains only.
  The operand-stream overlap rule (one chain's operands per compute tile) applies to all chains.
- **The device's default reaches L-T1 as `DeviceDescriptor::dataflow`**, from
  `DeploymentSpec::device_view`.
- **Optional record columns** (`dataflow`, `preload`, `streamed`) on the `.tflow` `chain` table
  and the `.dflow` `lt1_chains` table. A record without them reads as all-OS, as before.

## 3. Issues Encountered

- `tileflow/test_viewer.py` reviews raw HTML interpolations by exact text. The chain label's new
  `esc(...)` dataflow name changed one reviewed string, so its entry was updated.
- A test's initializer list mixed `const T*` and `T*`. It failed to compile, but ctest went on
  running the stale binary and reported 354/354. Caught by reading the build output, not the
  ctest summary.

## 4. Wrong Decisions

- **Step 1 let a fabric accumulator take the deployment's default.** The step-2 tests exposed
  it: under `fabric.dataflow: ws`, an OS program's in-fabric chains would have been timed WS.
  Fixed in step 1's PR (#465): a fabric accumulator is always OS.
- **Trusting a ctest summary after a failed build.** The build's error was in the output; the
  pass count was from an old binary. Lesson: check the build's exit status before reading test
  results.
