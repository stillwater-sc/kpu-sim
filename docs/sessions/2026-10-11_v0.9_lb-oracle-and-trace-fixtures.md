# v0.9 L-B Is the Oracle; Test Fixtures Are L-B Traces (retire-l0-derivations PR 1)

**Date:** 2026-10-11
**Version:** v0.9
**Status:** Complete (PR 1 of 3)
**Tests:** 269/269

## 1. Summary

#357 was merged, and the plan to retire the C++ L0 derivations
(`docs/plans/retire-l0-derivations.md`) was written and reviewed. PR 1 does two things:
- it makes L-B the oracle, and the one place a CSP program becomes an L0;
- it moves every test that used a derivation as a fixture or as a second oracle onto L-B traces.

## 2. Decisions

- **The L-B model is the oracle** (decided by the user in review, 2026-10-11).
  - The question was Q2 of the plan. I had recommended a test-only operator reference (naive
    A·B, act(A·B+b), P·A = L·U) as an independent second oracle.
  - The user decided otherwise: L-T1, L-T2 and L-CA are refinements of the behavioral model, so
    the behavioral model is the single source of truth for how a CSP program becomes an L0 trace
    of transactions and operations, and for its values.
- **L-B records the trace.** Before, `csp_reference` took the trace from `csp::lang::compile`
  (the walker's `TraceSink`), and the oracle was `TileProgramReference`'s replay of it; L-B was a
  level compared against that. Now:
  - the walker's L0 ops ride on the `ActionStream`, attached to the action they precede
    (`Emission::l0`);
  - `BehavioralInterpreter::begin(operands, record)` keeps them, and `trace()` returns them.
- **The replay is the trace's validation.** It must reproduce L-B bit for bit on every operand.
  A mismatch is reported as a kpu-sim defect (`replay_mismatch`), and kpu-run fails rather than
  write the file.
- **The oracle exists at every size.** L-B streams, so `--trace-limit` bounds only the trace.
  This removed the "no oracle and no L-B run" case: `kpu_run_csp_emit_needs_an_authority` became
  `kpu_run_csp_emit_l0_needs_a_trace`.
- **Kernel unit tests keep their naive math.** `test_tile_program` checks the shared L0 kernels
  (matmul against a naive product, LU by P·A = L·U) on its own inputs, replayed from a trace.
  - This tests the kernels L-B runs. It is not a second oracle for a program.
- **Rectangular tiles are hand-written programs.** kpu-csp-gen writes square tiles only, so
  `tests/program/csp/matmul_7x5x6_t3x2x4.csp` (clamped) and `matmul_6x4x8_t2x2x4.csp` (even)
  were added. Clamped square cases (LU 6/4, matmul 40/16) come from kpu-csp-gen.
- **Cross-schedule agreement replaces the shared derivation.** Several tests used to compare
  each schedule against one derived reference, which implied the schedules agree with each
  other. They now check that directly:
  - matmul col and row orientations;
  - linear placements per activation, at L-B and at L-CA.

## 3. Evidence

- **The corpus is unchanged, byte for byte.** `test_l0_corpus` passed on the first build after
  the change, so the trace L-B records is the trace `compile` produced.
- **The trace matches compile op for op.** A new test in `test_csp_run`, for matmul, linear and
  LU at 32/16, checks that L-B's trace equals `compile`'s op list in kind and label, carries the
  inputs, and replays to L-B's values.
- **kpu-run** replays bit-exact on kpu-csp-gen's LU 4/2, 4/4, 6/2, 6/4 and 64/32, on matmul
  40/16, and on both rectangular fixtures.
- **No assertion was removed, and none went from bit-exact to tolerance.** Literals changed in
  one place: `test_l0_serialization`'s pinned op line now has the trace's label, `line 12`.

## 4. Wrong decisions

- **Recommending an independent operator reference as the second oracle.** It would have been a
  second source of truth beside the behavioral model, a softer form of the second L0 source
  rejected in step 5. The refinement relationship between the levels already says which model
  answers for values.
