## 1. Summary

The C++ `.dflow` writer and reader carry int8 and int32 operands. The version-6 format already
defined them: a byte payload decoded per operand, `dflow_check.py`'s `ELEMENTS` and `decode`, and
exact integer comparison. Only the C++ side was fp32-only.

PR #413 (step 2, L-CA) was merged earlier today.

## 3. Technical Decisions

- **Decision 1: in memory the record keeps words; the bundle keeps widths.** `elements` stays a
  `vector<float>` of 32-bit words, as the operands hold them. Only the serializer knows widths.
  The recorder, `attach_lt1` and the tests are unchanged in shape.
- **Decision 2: an element must be named by both the format and the registry.** The format also
  defines fp16, bf16 and fp8. The registry cannot compute in them yet, so the C++ reader refuses
  them by name, and `dflow_check.py` remains the reader for RTL bundles that use them. Each format
  type the registry gains is accepted automatically.
- **Decision 3: the payload is written byte by byte, from the word's low bytes.** For fp32 this is
  the same little-endian bytes the old `memcpy` wrote, so existing bundles are unchanged. For int8
  it is the low byte of the zero-extended word, and the reader zero-extends it back, which is what
  `numeric::encode` writes. The round trip is therefore word-exact.
- **Decision 4: the reader decodes per snapshot from its byte offset.** It does not assume the
  snapshots are back to back. A bundle written elsewhere (the RTL's) may order its payload
  differently.

## 4. Issues Encountered

- Independent cross-check: Python decoded the bundle's final A, B and b with `dflow_check.decode`
  and recomputed C = A·B + b, wrapped to int32. It equals the recorded C. The C++ writer and the
  Python decoder agree on the bytes.

## 5. Wrong Decisions

- **I started a build while another was running.** `pgrep -a make` printed a build that wasn't mine
  (`simd_test_quad_dot` in `build-806-default`), and my command went on to build anyway, because
  the check was separated from the build by `;`, not gated with `&&`. That breaks the
  one-build-at-a-time rule, which exists because concurrent builds once took the server's load to
  400. **Lesson:** gate the build on the check (`if pgrep ...; then exit 1; fi` or `&&`), never
  `;`. Every later build this session did.
