## 1. Summary

`kpu-run` now takes a CSP program and executes it:
- L-B from the program's stream;
- L-CA through `CspDriver`, on the machine the deployment builds.

The trace's L0 is the oracle, and every level is compared bit-exactly, on every operand.
`kpu-csp-gen | kpu-run` works end to end for matmul and the linear operator at both levels, and
for LU at L-B. Each refusal names its reason.

## 2. Decisions

- **A separate execution path in `kpu-run`, not the virtual platform's.** The platform holds
  TilePrograms, and moving it to CSP programs is step 4. Until then, a `.csp` run goes through
  `driver::run_csp`, and the L0 path is unchanged.
- **A whitelist of options for a CSP run.** Anything else is refused by name, so an L0-path
  option is never silently ignored. `--algo` and the size options point to `kpu-csp-gen`.
- **`--level all` means every level, each run or skipped with a reason.** A named level that
  cannot run is a usage error (exit 2) with the same reason. A run never looks complete when a
  level was skipped.
- **The oracle is counted before it is built.** The stream is walked up to `--trace-limit`
  actions without keeping them, and only then compiled. Above the limit, the levels are compared
  with L-B, and the report says there is no oracle.
- **`CspDriver` reads every operand back from DRAM.** The every-operand comparison is what
  catches a level that writes an input.

## 3. Found on the way

**The oracle and `inout` results.** The first unfused-linear run had L-B and L-CA agreeing with
each other and both disagreeing with the oracle in 9,320 elements. C is `inout` because the
program reads it back, so it was given synthesized input values. The program's accumulator
starts from zero, but L0's MatMulAccum adds onto the operand's buffer: the oracle computed
`synthesized + A . B`.

An `inout` operand is an input only if the program reads it first. `csp_inputs` decides by
first touch, streaming until each `inout` operand is loaded (an input) or written (it starts at
zero). The stream ends early: operands are touched within a program's first actions.
