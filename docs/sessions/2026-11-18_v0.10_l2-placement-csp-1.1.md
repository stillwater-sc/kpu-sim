# Session: every L2 copy placed, csp 1.1 (#387 step 1)

**Date:** 2026-11-18
**Version:** v0.10 (in progress)
**Issues:** #387 (step 1 of 3), #401 (slice 2)

## 1. Summary

#401's slice 2 mirrors the RTL's whole-tile slot credits. The comparison of the RTL's model with
L-CA's (by a research agent) found that L-CA has most of the protocol under other names but no
per-slot state, no faults, transient L2 slots for unstaged copies, a dedup that supplies
unstated reuse, and a result slot taken at the drain. The user's decisions are recorded in the
plan, `docs/plans/slot-credits-at-lca.md`. This step places every L2 copy at the program level:
the language, the walker, L-B, the trace, the L-B record and the generator.

## 2. Technical Decisions

- **The user's** (plan §2): a result slot taken at the first compute; separate A and B credits;
  the walker places every L2 copy and the dedup goes; `l2 = N` required; and, for this step,
  csp 1.1, with csp 1.0 refused by its version.
- **Ring allocation**, not lowest-free: at L-B a copy's Feed frees its slot before the next Move,
  so lowest-free would reuse the same slots every call and nothing could double-buffer.
- **An unstaged copy is a one-Feed staging** (Move, Feed, L2Release), not a Feed that frees its
  slot. My first design added a freeing Feed; every consumer (the record, its checkers, the
  viewers, the trace's replay) already understands the staging lifecycle, and the freeing Feed
  failed all of them.
- **A result's slot is recorded as a partial with one merge**: the Combiner writes the drained
  result into its slot, which is written back once and released.
- **The timed levels run copies unplaced in this step** (`csp::unplaced`, the action's `copy`
  flag): L-CA's L2 is keyed by tile and cannot hold two copies of one tile, which ring placement
  produces. Steps 2 and 3 make L-T1 and L-CA execute the slots.

- **The walker is the authority for L2 capacity; the validator is a lower bound** (decided with
  the user after #496's third review round). The first design had the symbolic validator recount
  the walker's exact allocation: result slots, late stores pending across loop iterations, init
  copies. Each CodeRabbit round found another case where the two disagreed, because one pass over
  the program cannot see what the walker sees iteration by iteration. The validator now checks the
  slots a program states and one more per call. It never refuses a program the walker accepts,
  and the walker refuses the rest by line.

## 3. Issues Encountered

- **The migration of 89 machine clauses ran twice on 15 files** after the first run stopped on a
  non-UTF-8 file; every clause was recomputed from its original in git.
- **The migration also rewrote expected text** in tests that check refusals (a program with no
  L2, a capacity error); those were restored by hand.
- **Regenerating the corpus programs with the generator changed them** (today's generator writes
  `store ... late`), which moved the iteration counts. They were restored from git, with only
  `l2 = N` added.
- **A stale LU result** in the corpus, independent of this change: see the CHANGELOG.

## 4. Wrong Decisions

- **The freeing Feed** (above): a new lifecycle every consumer would have had to learn, when the
  existing one fit. Lesson: model a new case in the form the consumers already read.
- **Recording a copy's Feed op before its Move** (an argument evaluated before the call), so the
  trace said "fed" before "moved". The replay, which only checks slot bookkeeping, still matched
  L-B; `test_csp_lb_place` caught the order.
- **Regenerating corpus programs** rather than editing their clause: the corpus README calls
  regeneration a decision, not a chore.

- **A second model of the walker's L2 allocation in the validator** cost two review rounds and
  most of #496's findings. Lesson (saved as working practice): when a check would duplicate
  another component's exact accounting, make the exact one the authority and keep the other a
  cheap lower bound.
