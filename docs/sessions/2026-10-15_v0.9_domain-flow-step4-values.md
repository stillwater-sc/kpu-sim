## 1. Summary

The `.dflow` record carries tile values (format version 2), and the viewer's inspector shows them:
- Every operand's final tiles are always recorded, from L-B's result (plan Q2).
- With `kpu-run --dflow-values`, a selected tile is recorded wherever each action leaves it, so
  you can watch an accumulator grow across a k loop and follow a result from the fabric through L2
  and L3 to DRAM.
- The inspector draws a tile as a heatmap with stats and an element readout, at the current step
  or final.
- The review artifact now runs this version, with three tiles of the reference run recorded.

## 3. Technical Decisions

- **Decision 1: a snapshot is where the action leaves the tile.** Load, Writeback and Inherit
  leave it in L3; Move and Drain in L2; Feed and Call in the fabric; Store in DRAM. Release and
  Retain move nothing. A Call's snapshot is the fabric's accumulator after that call, which is
  what makes a k loop inspectable.
- **Decision 2: finals first in the cap.** Plan Q2 says finals are always recorded. The cap
  (default 64 MiB) reserves them before any snapshot; operands larger than the cap are not
  recorded, and the manifest says why. Snapshots stop at the first one that does not fit, and the
  manifest names that action (`values.cut_at`).
- **Decision 3: the format is named, and anything but float32 is refused.** The operands carry
  float32 today (`tile_check`'s `ElementFormat` refuses others), so the manifest says
  `"format": "float32"`, and the checker and the viewer refuse any other format rather than misread
  it.
- **Decision 4: version 2, with version 1 still read.** The C++ reader, the checker and the viewer
  accept both. A version-1 bundle shows "no tile values" in the inspector.
- **Decision 5: snapshot shape columns are `height`/`width`.** A column named `rows` collided with
  the checker's row-count key.

## 4. Issues Encountered

- The first checker run crashed: the snapshot table's `rows` column shadowed the table's row
  count in the checker's loader. The columns were renamed in the format (Decision 5).
- `test_unknown_version_is_unreadable` used version 2 as its unknown version; it now uses 99.

## 5. Wrong Decisions

- Naming a column `rows` in a format whose loaders key the row count by the same word. Caught
  before any bundle was committed.

## 6. Validation

- `test_domain_flow_record`, 12 cases (5 new):
  - values round-trip bit for bit;
  - every operand's final tiles equal L-B's result bit for bit, on three corpus programs;
  - matmul's C[1,2] is recorded as CALL x3, DRAIN, WRITEBACK, STORE in the right channels, and the
    accumulator changes with each call and ends as what is stored and final;
  - the cap stops snapshots after 5 and keeps the finals, and below the finals' size records none
    and says why;
  - the selection parses tiles, operands and `all`, and refuses malformed items and unknown

  its final value equal the bundle's. A mutation of `valueAt` (strict `<`) fails it.
- `kpu_run_csp_dflow_values_refuses`: an unknown operand exits 2 and writes nothing.
