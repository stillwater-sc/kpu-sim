**Date:** 2026-10-15

## 1. Summary

L-T1 has executed the program's L3 placement since step 5a; now its tile-flow record says where
each tile was. `.tflow` version 5 adds the L3 address (`l3_tile`, `slot`, `bank`) to every
residency and `l3_banks` to the manifest. The pyramid gains one row per slot, so the tile-flow
viewer's swimlanes draw each slot, and `tflow_check.py` checks the placement (TF12). CLAUDE.md no
longer says `.tflow` draws L3 pooled.

## 3. Technical Decisions

- **Decision 1: the L3 station stays pooled; the residency carries the address.** A slot is an
  address in the program's flat L3 (level 1), not a physical L3 tile of the floorplan, so a
  per-slot station would have claimed a place the record does not hold. The floorplan stays
  pooled and says why. Binding the flat L3 to physical tiles is level 2.
- **Decision 2: slot rows go in the pyramid, after every existing row.** The viewer draws the
  pyramid's rows generically, so the slot rows appear with no drawing change. Appending them
  keeps every existing row index, which the viewer and the tests rely on.
- **Decision 3: TF12 checks what the address promises.** A slot inside the L3's capacity, the
  bank equal to `slot % l3_banks` (the allocator's rule, `place.hpp`), and one tile per slot at a
  time. TF8 checks that the slot rows exist and recomputes each from the residencies.
- **Decision 4: version 4 is still read**, with no addresses (`kNoSlot`, `l3_banks` 0). The v4
  self-test now accepts both versions and adds TF12 and slot-row cases when it is given v5.

## 5a. Review (#376)

Five findings, all fixed, plus two the review did not name:
- **TF12 keyed slots by module (major).** A version-5 record is the program's flat L3, so a module
  other than 0 is now a TF12 violation, and exclusivity is checked by station and slot.
- **The slot inspector wrote the row name with `innerHTML` (major, XSS).** The tile-flow viewer had
  no escaping at all, and about a dozen statements wrote bundle or floorplan names (block names,
  kinds, clocks, row names, the device, operand names) into HTML. It gained `esc()`, every such
  statement uses it, and `test_viewer.py` scans them (it fails on the previous page).
- **Zero-length residencies** occupy no time and are no longer TF12 collisions.
- **Slot rows by station and slot**, in TF8's recompute and in the viewer's lookup.
- **The honesty note with a binding** now says the program slot is recorded and only the physical
  tile is derived.
- *Not named by the review:* `opText` treated only version 4 as a CSP record, so a v5 bundle would
  have labelled its actions with L0 op kinds. It now covers versions 4 and 5.
