## Goal

Comprehensive validation of the CSP-style timing model through:
1. Schedule generators for common DNN operations (matmul, conv2d, softmax, layernorm, batchnorm)
2. Livelock test suite validating detection and avoidance strategies
3. Static schedule validation infrastructure

## Architecture

### Schedule Generator Interface

```cpp
namespace sw::kpu::timing::schedule {

enum class ScheduleOpType { LOAD, STORE, MOVE, WRITEBACK, FEED, DRAIN };

struct ScheduleOperation {
    ScheduleOpType type;
    TileDescriptor tile;
    bool transpose = false;
};

struct ScheduleMetadata {
    std::string name;
    Size a_tiles, b_tiles, c_tiles;
    Size Ti, Tj, Tk;
};

struct ScheduleResult {
    std::vector<ScheduleOperation> operations;
    ScheduleMetadata metadata;
};

class IScheduleGenerator {
public:
    virtual ~IScheduleGenerator() = default;
    virtual ScheduleResult generate() = 0;
    virtual std::string name() const = 0;
};

} // namespace
```

### MatMul Schedule Generator

```cpp
class MatMulScheduleGenerator : public IScheduleGenerator {
public:
    struct Config {
        Size M, N, K;                    // Problem dimensions
        Size Ti = 16, Tj = 16, Tk = 16;  // Tile dimensions
        Size element_size = 4;           // FP32

        enum class Strategy {
            OUTPUT_STATIONARY,    // C stays in accumulators
            INTERLEAVED_AB,       // A-B-A-B ordering (livelock-safe)
            PREFETCH_NEXT         // Overlap load with compute
        };
        Strategy strategy = Strategy::INTERLEAVED_AB;
    };

    explicit MatMulScheduleGenerator(const Config& config);
    ScheduleResult generate() override;
};
```

### Livelock Avoidance Strategies

1. **Partitioned Credits**: A/B/C segregation prevents one matrix type from monopolizing buffers
2. **Interleaved Scheduling**: A-B-A-B tile ordering ensures balanced buffer usage
3. **Work-Conserving**: Scan queues for any ready tile, not just head
4. **Priority Aging**: Prefer oldest tiles to prevent starvation

## Key Design Decisions

1. **Header-only generators**: Minimal build dependencies, easy integration
2. **TileDescriptor output**: Generators produce tile sequences, not DMInstruction (keeps timing model ISA-independent)
3. **INTERLEAVED_AB default**: Safest strategy for livelock avoidance
4. **Static validation**: Fast analysis without simulation, catches issues early
5. **PartitionedCreditPool integration**: Existing infrastructure provides the livelock prevention mechanism
