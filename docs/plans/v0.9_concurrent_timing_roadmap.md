## Executive Summary

The current transactional timing model processes instructions sequentially, missing
the natural concurrency of the KPU's credit-based dataflow architecture. This results
in **4-8x overestimation of execution time** for memory-bound workloads.

The v0.9.0 release transforms the timing model to use Communicating Sequential
Processes (CSP) semantics where DMA, BlockMover, and Streamer run as concurrent
processes synchronized by credits and tag CAM matches.

---

## Problem Statement

### Current State (v0.8.x)
- Sequential instruction dispatch (single PC)
- No concurrent DMA across A/B matrices
- No pipelining between memory hierarchy levels
- Timing overlay computed post-hoc, not during simulation
- Resource parallelism only (not instruction-level)

### Target State (v0.9.0)
- Multiple concurrent component processes
- True credit-based flow control
- Tag CAM matching for data availability
- Discrete event simulation
- 4-8x timing accuracy improvement
