# Version Management

KPU Simulator uses **git tags as the single source of truth** for versioning. This ensures consistency between C++, Python, and release artifacts.

## Semantic Versioning

We follow [Semantic Versioning 2.0.0](https://semver.org/):

```
MAJOR.MINOR.PATCH

0.x.y  - Pre-production development (API may change)
1.0.0  - First stable release (API stability guaranteed)
```

### Version Increments

| Change Type | Example | When to Use |
|-------------|---------|-------------|
| **MAJOR** | 0.x → 1.0 | Breaking API changes |
| **MINOR** | 0.2 → 0.3 | New features, backwards compatible |
| **PATCH** | 0.2.0 → 0.2.1 | Bug fixes, backwards compatible |

## How It Works

### Git Tags

Version is derived from git tags using `git describe`:

```bash
# Release version (exact tag)
$ git describe --tags
v0.3.0

# Development version (commits after tag)
$ git describe --tags
v0.3.0-5-g1a2b3c4
#      ^   ^
#      |   +-- commit hash
#      +-- commits since tag
```

### Components

| Component | Source | Output |
|-----------|--------|--------|
| **CMake** | `cmake/Version.cmake` | `build/generated/sw/kpu/version.hpp` |
| **Python** | `setuptools-scm` | `python/kpu/_version.py` |
| **Release Script** | `scripts/release.sh` | Git tags |

## Usage

### Creating a Release

```bash
# Check current version
./scripts/release.sh --current

# Create a new release tag
./scripts/release.sh 0.3.0

# Create and push in one step
./scripts/release.sh 0.3.0 --push
```

### In C++ Code

```cpp
#include <sw/kpu/version.hpp>

std::cout << "Version: " << sw::kpu::VERSION_STRING << std::endl;
// Output: "0.3.0"

if (sw::kpu::version_at_least(0, 3, 0)) {
    // Use new feature
}
```

### In Python Code

```python
import kpu

print(kpu.__version__)  # "0.3.0"

# Or import the version module directly
from kpu._version import __version__, version_at_least

if version_at_least(0, 3, 0):
    # Use new feature
```

### In CMake

```cmake
# After include(Version)
message(STATUS "Building KPU ${KPU_VERSION_STRING}")

if(KPU_VERSION_MAJOR GREATER_EQUAL 1)
    # Stable API
endif()
```

## Development Workflow

### Normal Development

1. Work on feature branch
2. Merge to main
3. Version shows as `0.3.0-5-g1a2b3c4` (dev version)

### Creating a Release

1. Ensure all tests pass
2. Update CHANGELOG.md
3. Run `./scripts/release.sh X.Y.Z --push`
4. Create GitHub Release from tag
5. Version now shows as `X.Y.Z` exactly

### Hotfix

1. Create hotfix branch from tag
2. Fix bug
3. Tag as `vX.Y.Z+1` (patch increment)
4. Merge back to main

## Version Files (Generated)

These files are **auto-generated** - do not edit manually:

| File | Generated By | Purpose |
|------|--------------|---------|
| `build/generated/sw/kpu/version.hpp` | CMake | C++ version constants |
| `build/generated/kpu/_version.py` | CMake | Python version (cmake build) |
| `python/kpu/_version.py` | setuptools-scm | Python version (pip install) |

## CI/CD Integration

### GitHub Actions

```yaml
- name: Get version
  id: version
  run: echo "version=$(git describe --tags --always)" >> $GITHUB_OUTPUT

- name: Build
  run: cmake -DKPU_VERSION_STRING=${{ steps.version.outputs.version }} ...
```

### Release Automation

```yaml
on:
  push:
    tags:
      - 'v*'

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build release
        run: |
          cmake --preset release
          cmake --build --preset release
      - name: Create GitHub Release
        uses: softprops/action-gh-release@v1
```

## Fallback Behavior

If git is not available or no tags exist:

| Scenario | Version |
|----------|---------|
| No git | `0.2.0-dev` (fallback) |
| No tags | `0.2.0-dev` (fallback) |
| Exact tag | `0.3.0` (release) |
| After tag | `0.3.0-dev5+g1a2b3c4` (dev) |

## Best Practices

1. **Tag releases, not commits** - Tags are permanent markers
2. **Use annotated tags** - `git tag -a v0.3.0 -m "Release 0.3.0"`
3. **Never move tags** - Once pushed, tags should be immutable
4. **Update CHANGELOG first** - Before tagging, document changes
5. **Test before tagging** - All CI checks should pass
