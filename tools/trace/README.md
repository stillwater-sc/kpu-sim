# KPU Trace Tools

Command-line and visualization tools for analyzing LPDDR5 memory controller traces.

## Overview

This directory contains tools for working with Chrome Trace Event Format (JSON) files
generated by the LPDDR5 memory controller patterns.

| Tool | Type | Purpose |
|------|------|---------|
| `kpu-trace-summary` | C++ CLI | Text-based trace analysis and validation |
| `serve-trace.py` | Python | Local HTTP server for HTML visualization |

## Quick Start

```bash
# Generate a trace
./build/patterns/memory/lpddr5/lpddr5_page_hits

# Analyze with CLI (works everywhere)
./build/tools/trace/kpu-trace-summary traces/memory/lpddr5/single-bank/page_hits_trace.json

# Launch web viewer (requires display)
./tools/trace/serve-trace.py traces/memory/lpddr5/single-bank/page_hits_trace.json
```

## kpu-trace-summary

A C++ command-line tool for analyzing LPDDR5 traces. Works on headless servers,
in CI/CD pipelines, and anywhere a terminal is available.

### Usage

```bash
kpu-trace-summary <trace.json> [options]

Options:
  --verbose, -v    Show per-transaction details
  --json, -j       Output in JSON format
  --validate       Validate timing constraints (exit 1 on failure)
  --help, -h       Show help message
```

### Examples

**Basic Summary:**
```bash
$ ./build/tools/trace/kpu-trace-summary traces/memory/lpddr5/single-bank/page_hits_trace.json

LPDDR5 Trace Summary: page_hits_trace.json
==================================================
Transactions: 16 (16 READ, 0 WRITE)
Total Cycles: 366
Commands: 17 (1 ACT, 16 CAS, 0 PRE)
Page Hits: 15/16 (93.8%)

Bank Utilization:
  Bank 0: ##################################       17 cmds

Latency Distribution (cycles):
  Min: 22 | Avg: 22.9 | P50: 22 | P95: 36 | P99: 36 | Max: 36

Timing Validation:
  [PASS] All invariants passed
```

**Verbose Mode (per-transaction details):**
```bash
$ ./build/tools/trace/kpu-trace-summary trace.json --verbose

...
Transaction Details:
----------------------------------------------------------------------
  TXN_ID    TYPE     START       END   LATENCY    PAGE_HIT      CMDS
----------------------------------------------------------------------
       1    READ        42        78        36          no         2
       2    READ        78       100        22         yes         1
       3    READ       100       122        22         yes         1
...
```

**JSON Output (for scripting):**
```bash
$ ./build/tools/trace/kpu-trace-summary trace.json --json

{
  "file": "trace.json",
  "summary": {
    "total_transactions": 16,
    "read_count": 16,
    "write_count": 0,
    "page_hits": 15,
    ...
  },
  "latency": {
    "min": 22, "max": 36, "avg": 22.9,
    "p50": 22, "p95": 36, "p99": 36
  },
  "validation": {
    "status": "PASSED",
    "violation_count": 0
  }
}
```

**CI/CD Integration:**
```bash
# Returns exit code 1 if validation fails
./build/tools/trace/kpu-trace-summary trace.json --validate
echo $?  # 0 = pass, 1 = fail, 2 = error
```

### Output Fields

| Field | Description |
|-------|-------------|
| Transactions | Total user requests (grouped by txn_id) |
| Total Cycles | Simulation duration |
| Commands | DRAM commands: ACT (activate), CAS (read/write), PRE (precharge) |
| Page Hits | Requests that found row already open (no ACTIVATE needed) |
| Bank Utilization | Visual bar chart of commands per bank |
| Latency | Request latency statistics in cycles |
| Timing Validation | Invariant check results |

### Validated Invariants

| ID | Description | Severity |
|----|-------------|----------|
| INV-001 | Every txn_id must have exactly one data operation | ERROR |
| INV-002 | ACTIVATE/PRECHARGE must belong to valid transactions | ERROR |
| INV-003 | Commands must be temporally ordered (ACT→CAS→PRE) | ERROR |
| INV-100 | tRCD constraint (ACT complete before CAS) | ERROR |

## serve-trace.py

A Python HTTP server that serves the HTML visualization tools with automatic
trace data injection. Provides a web-based UI for interactive trace analysis.

### Usage

```bash
serve-trace.py <trace.json> [options]

Options:
  --port, -p PORT     Server port (default: 8080)
  --no-browser        Don't auto-open browser
  --viewer, -v NAME   Open specific viewer directly
  --host HOST         Server host (default: localhost)
```

### Examples

```bash
# Serve trace and open browser
./tools/trace/serve-trace.py traces/memory/lpddr5/single-bank/page_hits_trace.json

# Custom port
./tools/trace/serve-trace.py trace.json --port 8888

# Server only (for remote access)
./tools/trace/serve-trace.py trace.json --no-browser --host 0.0.0.0

# Open specific viewer
./tools/trace/serve-trace.py trace.json --viewer swimlane
```

### Available Viewers

The server provides access to four visualization tools located in
`traces/memory/lpddr5/tools/`:

| Viewer | URL Path | Description |
|--------|----------|-------------|
| Swimlane | `/viewer/swimlane` | Horizontal pipeline flow visualization |
| Timing | `/viewer/timing` | Classic DRAM timing waveforms |
| Block Diagram | `/viewer/blockdiagram` | Animated architectural view |
| Bank Analyzer | `/viewer/bank_analyzer` | Per-bank state analysis |

### API Endpoints

| Endpoint | Description |
|----------|-------------|
| `/` | Index page with links to all viewers |
| `/trace.json` | Raw trace data (JSON) |
| `/viewer/<name>` | Specific viewer HTML |

### Remote Access

For headless servers, you can use SSH port forwarding:

```bash
# On the server
./tools/trace/serve-trace.py trace.json --no-browser --host 0.0.0.0 --port 8080

# On your local machine
ssh -L 8080:localhost:8080 user@server

# Then open http://localhost:8080 in your local browser
```

## Integration with Patterns

The LPDDR5 pattern executables automatically generate traces:

```bash
# Run pattern (generates trace to default location)
./build/patterns/memory/lpddr5/lpddr5_page_conflicts

# Trace written to: traces/memory/lpddr5/single-bank/page_conflicts_trace.json

# Analyze immediately
./build/tools/trace/kpu-trace-summary traces/memory/lpddr5/single-bank/page_conflicts_trace.json
```

## Trace File Format

Traces use [Chrome Trace Event Format](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU):

```json
[
  {"name": "process_name", "ph": "M", "pid": 16, "args": {"name": "LPDDR5_BANK"}},
  {"name": "ACTIVATE", "cat": "LPDDR5_BANK", "ph": "X",
   "ts": 13125.0, "dur": 4375.0, "pid": 16, "tid": 0,
   "args": {
     "txn_id": 1,
     "cycle_issue": 42,
     "cycle_complete": 56,
     "desc": "ACTIVATE Ch0 Bank0"
   }}
]
```

Key fields:
- `txn_id`: Links commands belonging to the same user request
- `cycle_issue` / `cycle_complete`: Timing in simulation cycles
- `pid`: Channel identifier
- `tid`: Bank number

## Building

The C++ tool is built as part of the normal build:

```bash
cmake --preset release
cmake --build --preset release --target trace-summary
```

The Python script requires no build step (Python 3.6+).
